# Research note: Share tab

This note records, for each function of the Share tab, how GIS programs offer it, which standard or existing
function Lynkeus uses for it, the choices of Lynkeus that come from no source, the limits found and what was tried.
Every source was read on 14 Nov 2026.

The rows "Tried" describe runs of 14 Nov 2026 in Chromium, driven by Playwright 1.65.1, on a copy of the site
that was served with the security policy of the site, in a window of 1440 by 900 pixels unless another size is
named. No error was written to the console and no request failed in these runs. The background maps were Blue
Marble and OpenStreetMap; no NISAR layer was on the map. After these runs the work continued without a browser.
Each row therefore also names what was changed afterwards and is covered by the tests of the code only. Firefox
and Safari were not tried.

## Map image

| | |
|---|---|
| ArcGIS Pro | On the Share tab, Export Map opens the Export pane for the active map view. "The map view determines the extent and scale of the exported map, but you can set the export size in pixels." The pane has Width and Height, a button that preserves the aspect ratio, and the option Write world file. When the proportions of the export differ from those of the view, "the map may be cropped": a view of 1920 by 1080 pixels exported as 200 by 200 pixels loses content at the left and the right. The raster formats are BMP, JPEG, PNG, TIFF, TGA and GIF, and "for maps, PNG is often the best raster format", because its lossless compression keeps text and lines legible ([Export a map or layout](https://pro.arcgis.com/en/pro-app/latest/help/sharing/overview/export-a-map-or-layout.htm)). A map view is exported without map elements; those belong to a layout. |
| QGIS | Project, Import/Export, Export Map to Image opens the Save Map as Image dialog: the extent (the current view by default), the scale, the resolution, and the output width and height in pixels, which are "based by default on the current resolution and extent" and whose ratio can be locked. Draw active decorations exports the scale bar, the title, the grid and the north arrow with the map, and Append georeference information writes a world file ([The map view, Exporting the map view](https://docs.qgis.org/3.40/en/docs/user_manual/map_views/map_view.html)). The decorations are Grid, Title Label, Copyright Label, Image, North Arrow, Scale Bar and Layout Extents (same page). |
| Function used | OpenLayers 10.11.0 accepts a canvas as the target of a map: "For use in workers or when exporting a map, use an `OffscreenCanvas` or `HTMLCanvasElement` as target" (documentation of the option `target` in `ol/Map.js` of the npm package). The map then takes the size of the canvas, and the renderer draws every layer into it in the same frame, whether the layer has a 2D or a WebGL canvas (`ol/renderer/Composite.js`, read in the package). The example [Map Export](https://openlayers.org/en/latest/examples/export-map.html) uses this, and waits for the event `rendercomplete`. The example [Export PDF](https://openlayers.org/en/latest/examples/export-pdf.html) gives the rule for a picture of another size: the resolution of the view is divided by the ratio of the two sizes. Lynkeus moves the map to a canvas of the size of the picture, gives it a view of its own for that moment, and returns the map and the view of the user afterwards. |
| File format | PNG. The browser writes the file with `HTMLCanvasElement.toBlob`. It writes no resolution, so Lynkeus adds the chunk `pHYs` of the PNG specification, which holds the pixels per metre along both axes and the unit specifier 1 for the metre ([PNG Specification, Third Edition, 11.3.4.3 pHYs Physical pixel dimensions](https://www.w3.org/TR/png-3/)). |
| Choices of Lynkeus | The picture is filled by what the map shows and shows nothing beyond it, as in ArcGIS Pro. With the size "The map as the screen shows it", a higher resolution gives more pixels in proportion, as in QGIS. The resolutions offered are 96, 150 and 300 dots per inch; 96 is the resolution of a style sheet, in which an inch holds 96 pixels. A side has between 100 and 8000 pixels. The drawing may take two minutes. The elements follow the decorations of QGIS: a scale bar, a north arrow on a rotated map, and the lines of sources, which cannot be switched off. Their sizes are multiplied by the resolution divided by 96, so that they keep their size on paper. A place where no layer has drawn is white. The file is named `lynkeus-map-` with the date and the time of the user's clock. These numbers and names come from no source. |
| Limits | No world file is written, so the picture carries no coordinates. The text and the lines of vector layers keep their size in pixels, so they are finer on a picture of a higher resolution. The map is counted in pixels of the style sheet: on a screen with more device pixels, the picture of the screen has the pixels of the style sheet, not those of the device. While a picture is drawn, the map is drawn on another canvas, so the map of the page may be empty for that time; a screenshot taken while a picture of 300 dots per inch was drawn still showed the map, so an empty map was not seen. The north arrow is right for Web Mercator, where north has one direction over the whole map. |
| Tried | The map had 1152 by 745 pixels. The picture of the screen had 1152 by 745 pixels and the chunk `pHYs` with 3780 pixels per metre (96.012 dots per inch). At 300 dots per inch the picture had 3600 by 2328 pixels, 299.9994 dots per inch in the file, and was drawn in 2.6 seconds; at 150 dots per inch it had 1800 by 1164 pixels. Pictures of 500 by 500 pixels, of twice the size of the map, of a map rotated by 30 degrees and on a screen with a device pixel ratio of 2 were saved as well. The place of the map in a picture was compared with a mosaic of 80 tiles of Blue Marble at zoom level 8, placed by the formulas of Web Mercator in a separate program: the picture of the screen at zoom level 8 was identical to the mosaic in every value (0 of 2,263,680 differ outside the plates of the elements), and so was the picture of twice the size of a view at zoom level 7; a shift of one pixel gave a mean difference of 1.8 to 2.0. The pictures that are resampled (500 by 500 pixels; 300 dots per inch) had their smallest difference at no shift (1.19 and 0.81, against 4.15 and 2.62 at a shift of 3 and 6 pixels). A width of 50 pixels showed the sentence of the fault, and the button Save could not be used. A map with OpenStreetMap alone at 150 dots per inch gave a white picture with a scale bar; such a picture is now refused with a sentence that names the remedy, and this refusal was not tried in a browser. A picture with a NISAR layer, which is drawn with WebGL, was not tried. |

## Scale bar and north arrow

| | |
|---|---|
| OpenLayers | The scale line computes the ground length of a pixel at the centre of the view with `getPointResolution`, and chooses a length of 1, 2 or 5 times a power of ten (`ol/control/ScaleLine.js`, read in the package; [ScaleLine](https://openlayers.org/en/latest/apidoc/module-ol_control_ScaleLine-ScaleLine.html)). The rotation of a view is "in radians (positive rotation clockwise, 0 means North)" ([View](https://openlayers.org/en/latest/apidoc/module-ol_View-View.html)). |
| Function used | `getPointResolution` of OpenLayers, with the same lengths. The bar is the longest such length that is not wider than 240 pixels at 96 dots per inch, nor than three tenths of the picture. |
| Choices of Lynkeus | The bar has two parts for a length that starts with 1 or 2 and five for one that starts with 5, black and white in turn, with 0 at its start and the length with its unit at its end. Web Mercator enlarges the map with latitude, so a scale bar is exact at one latitude only. When the scale at a corner of the picture differs from the scale at its centre by more than 1 per cent, the bar names the latitude at which it is exact. The limit of 1 per cent comes from no source. |
| Tried | At zoom level 8 and latitude 42.775 degrees north a pixel is 448.854 metres, so 100 kilometres are 222.79 pixels; the bar of the picture was 223 pixels long and was labelled 100 km, with the note "at latitude 42.8° N". On the picture of a map rotated by 30 degrees clockwise, the arrow pointed up and to the right by that angle. |

| | |
|---|---|
| OpenStreetMap, attribution | "Static images must be generally attributed the same way as interactive maps." For printed maps and similar media, such as PDF files, "The URL to openstreetmap.org/copyright must be printed out." The text "© OpenStreetMap contributors" is acceptable ([Attribution Guidelines](https://osmfoundation.org/wiki/Licence/Attribution_Guidelines)). The Licence and Legal FAQ states that a screenshot of the map must be attributed on the image ([Licence and Legal FAQ](https://osmfoundation.org/wiki/Licence/Licence_and_Legal_FAQ), read through a search result). |
| OpenStreetMap, tiles | "Bulk downloading is any pre-emptive fetching of tiles other than those a user is actively viewing." Permitted is "normal interactive viewing by a human where the client requests only the tiles needed for the current viewport". "Offline use is not permitted on tile.openstreetmap.org." ([Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/)). |
| NASA GIBS | "NASA promotes full and open sharing of data. We ask that users who make use of GIBS in their clients or when referencing it in written or oral presentations to add the following acknowledgment: We acknowledge the use of imagery provided by services from NASA's Global Imagery Browse Services (GIBS), part of NASA's Earth Science Data and Information System (ESDIS)." ([GIBS API for Developers](https://nasa-gibs.github.io/gibs-api-docs/)). The page states no limit on the number or the use of the images. |
| Choices of Lynkeus | A picture and a layout carry, for Blue Marble, the acknowledgement of GIBS word for word, for the imagery of a date, the line of its day and instrument and then the same acknowledgement, and for OpenStreetMap "© OpenStreetMap contributors, openstreetmap.org/copyright". Any other layer gives the attributions of its OpenLayers source, with the address of each link written after its text. OpenStreetMap enters a picture only when the picture is made of the pixels that the screen shows: the size of the map or a part of it, at the scale of the screen. Such a picture needs no tile that the user is not viewing. A picture of another size or resolution would ask for other tiles, which the tile usage policy does not permit, so OpenStreetMap is left out of it; the form says so before the picture is made, and the outcome says so afterwards. This reading of the policy is the choice of Lynkeus; the policy does not name pictures of a map. Blue Marble and the imagery of a date enter a picture of any size. When OpenStreetMap is the only layer of the map, a picture that must leave it out is refused. |
| Tried | The picture of the screen with OpenStreetMap carried its line. During the picture of 150 dots per inch the browser sent no request to tile.openstreetmap.org, the form showed the note before, and the outcome was a warning. The lines of the imagery of a date were not tried in a browser. |
| Not read | The EOSDIS Data Use and Citation Guidance on earthdata.nasa.gov: the site refused the request of the server (HTTP 403). |

## Reading the pixels of the map

| | |
|---|---|
| Standard | "As soon as you draw into a canvas any data that was loaded from another origin without CORS approval, the canvas becomes tainted", and `getImageData()`, `toBlob()` and `toDataURL()` then throw a `SecurityError`. An image element asks for this approval with the attribute `crossorigin`, and the server grants it with the header `Access-Control-Allow-Origin` ([MDN, Use cross-origin images in a canvas](https://developer.mozilla.org/en-US/docs/Web/HTML/How_to/CORS_enabled_image)). |
| Measured | 14 Nov 2026, 15:32 UTC, from the server of Lynkeus, with and without the header `Origin: https://lynkeus.nkua.cloud`: `https://gibs.earthdata.nasa.gov/wmts/epsg3857/best/BlueMarble_ShadedRelief_Bathymetry/default/GoogleMapsCompatible_Level8/3/2/2.jpeg` and `https://tile.openstreetmap.org/3/2/2.png` both answered 200 with `access-control-allow-origin: *`. |
| Function used | The background maps ask for their images with `crossOrigin: "anonymous"` (`web/src/map/baseMaps.ts`). The images still load as images, so the security policy of the site (`img-src`) covers them as before. |
| Choices of Lynkeus | When the browser refuses to read a picture, the picture is drawn once more without the background maps, and the outcome says that the background map was left out. If the picture still cannot be read, nothing is saved and the reason is given. |
| Tried | The pictures with Blue Marble and with OpenStreetMap were read and saved; the browser refused none. The second drawing without the background maps was therefore never needed, and it is covered by a test only. |

## Saving a file

| | |
|---|---|
| Standard | A link with the attribute `download` saves its target as a file, and the attribute gives the name of the file. It "only works for same-origin URLs, same-origin `blob:`, and `data:` schemes" ([MDN, the anchor element](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/a)). |
| Function used | The content is a `Blob`, `URL.createObjectURL` gives it an address of the page itself (`blob:`), and a click on a link with that address and the attribute `download` saves it. The address is released after 60 seconds, a number that comes from no source. |
| Security policy | The policy of the site is `default-src 'self'; img-src 'self' https://gibs.earthdata.nasa.gov https://tile.openstreetmap.org; frame-ancestors 'none'`. A download is not a load of a script, a style, an image or a frame, and it sends no request, so no directive of this policy concerns it. An image with a `blob:` or `data:` address would be refused by `img-src`; no function of the Share tab shows one. |
| Tried | Under the security policy of the site, the area and every picture were saved through a `blob:` address, and the console named no breach of the policy. |

## Area

| | |
|---|---|
| Standard | RFC 7946, The GeoJSON Format ([rfc-editor.org](https://www.rfc-editor.org/rfc/rfc7946)). Section 3.1.6: a linear ring is closed, has four or more positions, and "exterior rings are counterclockwise". Section 3.3: a FeatureCollection has the member `features`. Section 4: the coordinate reference system is WGS 84, with longitude before latitude, and no other can be named. Section 5: the member `bbox` gives west, south, east, north. Section 12: the media type is `application/geo+json`, and the file ending is `.json` or `.geojson`. |
| GIS programs | ArcGIS Pro and QGIS were not read for this function. |
| Choices of Lynkeus | The file is a FeatureCollection with one Feature, a Polygon with one ring that starts at the south-west corner. A collection is written, and not a single feature, because programs that read vector files expect a list of features. The feature has the property `name` with the value "Area". Each coordinate is written as the area holds it, without rounding, so that the file gives back the same area. The file is named `lynkeus-area.geojson`. |
| Limits | An area of Lynkeus does not cross the meridian of 180 degrees, so section 3.1.9 on that meridian does not apply. |
| Tried | With the area of the sample files (west -71.2, south 42.6, east -70.75, north 42.95) the browser saved `lynkeus-area.geojson`, 668 bytes, and the message was "The area was saved as lynkeus-area.geojson." The saved file was read back: a FeatureCollection with the member `bbox`, one Polygon, five positions, the first equal to the last, counterclockwise. |

## Layout

| | |
|---|---|
| ArcGIS Pro | "A page layout is a collection of map elements organized on a virtual page designed for map printing. Common map elements include one or more map frames (each containing an ordered set of map layers), a scale bar, a north arrow, a map title, descriptive text, and a legend. For geographic reference, you can add grids or graticules." A layout has a landscape or a portrait orientation ([Layouts in ArcGIS Pro](https://pro.arcgis.com/en/pro-app/latest/help/layouts/layouts-in-arcgis-pro.htm)). Export Layout writes the page, among other formats as PDF ([Export a map or layout](https://pro.arcgis.com/en/pro-app/latest/help/sharing/overview/export-a-map-or-layout.htm)). |
| QGIS | The print layout holds "the QGIS 2D or 3D map canvas, text labels, images, legends, scale bars, basic shapes, arrows, attribute and simple tables, elevation profiles and HTML frames" ([Overview of the Print Layout](https://docs.qgis.org/3.40/en/docs/user_manual/print_composer/overview_composer.html)), and is exported as an image, as SVG or as PDF at an export resolution in dots per inch ([Creating an Output](https://docs.qgis.org/3.40/en/docs/user_manual/print_composer/create_output.html)). |
| Standard | CSS Paged Media Module Level 3: the descriptor `size` of the rule `@page` takes the values `A4`, "210 mm wide and 297 mm high", and `A3`, "297mm wide and 420mm high", and a length for each side; a named page is chosen by the property `page` of an element ([W3C](https://www.w3.org/TR/css-page-3/)). |
| Function used | The print function of the browser, `window.print()`, whose print window prints the page or saves it as a PDF file. No library is added. The page of the layout is an element of the document that a style sheet for print shows alone, on a named page of the chosen paper size. The map on it is the canvas on which the picture was drawn; the title, the marks of the coordinate frame, the scale, the projection, the date and the sources are text, so they stay text in the PDF file. |
| Choices of Lynkeus | A4 and A3, portrait and landscape. The page has a margin of 10 millimetres, as its own padding: the page of the style sheet has no margin, so the browser has no room for its own header and footer. The page is first laid out without the map, the room that the title and the foot leave is measured, and the map is drawn as a picture of that size. The resolution "The pixels that the screen shows" takes the largest part of the map on the screen that has the proportions of the frame, at the scale of the screen, so OpenStreetMap can be printed; 150 and 300 dots per inch draw the map anew. The page states the scale as a ratio, with the latitude at which it holds, the projection with its EPSG code, the version of Lynkeus and the date. The title has at most 120 characters. The title of the document is the title of the layout while the print window is open, because the browser proposes it as the name of the PDF file. These numbers come from no source. |
| Limits | The elements have fixed places; they cannot be moved or resized as in a layout of ArcGIS Pro or QGIS. The scale cannot be set to a round number. The scale holds when the page is printed at its full size; a print window that scales the page to another paper changes it. A browser that does not know named pages prints the page on the paper that the user chooses in the print window; Chromium knows them. |
| Tried | The page of the layout stood in the document at its true size: 1122.5 by 793.7 pixels for A4 landscape (297 by 210 millimetres) and 1122.5 by 1587.4 pixels for A3 portrait. On A4 landscape with the pixels of the screen the map frame was 267.01 by 153.57 millimetres, the picture 1152 by 726 pixels, and the page stated "Scale 1:1,936,557 at latitude 42.8° N"; on A3 portrait at 150 dots per inch the picture had 1577 by 2234 pixels and the page stated "Scale 1:884,062". Both ratios equal the ratio computed in a separate program from the size of the frame and the ground length of a pixel. The title of the document was the title of the layout during the print and "Lynkeus" afterwards, and the page of the layout left the document. The PDF function of the test program wrote the layout on a page of the chosen paper (297 by 209.9 millimetres; 297 by 420.2 millimetres), but before it a page with the application: the rule that hides the application lost against a rule of the site with an id. The rule is now marked `!important`. A4 portrait with the pixels of the screen failed, because the limits of the resolution of the form were applied to the resolution of the print; they no longer are. Neither correction was tried in a browser, and the print window of a browser itself was never opened by hand. |

## Coordinate frame

| | |
|---|---|
| ArcGIS Pro | "For geographic reference, you can add grids or graticules" to a layout ([Layouts in ArcGIS Pro](https://pro.arcgis.com/en/pro-app/latest/help/layouts/layouts-in-arcgis-pro.htm)). |
| QGIS | The decoration Grid of the map view, and the grids of a map item in a print layout ([The map view](https://docs.qgis.org/3.40/en/docs/user_manual/map_views/map_view.html)). The settings of a grid in a layout were not read. |
| OpenLayers | The graticule layer chooses its step from the list 90, 45, 30, 20, 10, 5, 2, 1 degrees, 30, 20, 10, 5, 2, 1 minutes and 30, 20, 10, 5, 2, 1 seconds (`ol/layer/Graticule.js`, read in the package). |
| Choices of Lynkeus | The frame marks where the meridians and the parallels of a round step meet the four sides of the map, and writes their angles in degrees, minutes and seconds of WGS 84 with the letter of the hemisphere. The step is the largest one of the list of OpenLayers that divides the span of the map into at least four parts; the number four comes from no source. Each side is followed in 64 pieces and a crossing is found by halving, so the marks are right for a rotated map. The top and the bottom carry the meridians and the left and the right the parallels; on a map that is turned by more than 45 degrees from north it is the other way round. No lines are drawn across the map. |
| Limits | A side carries one kind of line. On a map with north up these are all its marks. On a rotated map the parallels also meet the top and the bottom, and the meridians the left and the right; these crossings are not marked. |
| Tried | The places of the marks on the page were compared with places computed in a separate program: 26 marks on a map with north up and 24 on a map rotated by 30 degrees lay within 0.0005 pixels of the picture, and the middle of each label within 0.013 pixels of its mark. On the rotated map, labels of meridians and of parallels stood on the same side and ran into each other. For that reason a side now carries one kind of line; this change was not tried in a browser. |

## Link to this map

| | |
|---|---|
| OpenStreetMap | The address of a map is `https://www.openstreetmap.org/#map=<zoom level>/<latitude>/<longitude>`, with `&layers=<layer code>` for the layers shown ([Browsing](https://wiki.openstreetmap.org/wiki/Browsing)). |
| ArcGIS Online | Map Viewer reads URL parameters, among them `center=20,45`, `level=8`, `extent=` with four numbers, and `basemapUrl=` ([Use URL parameters to modify maps](https://doc.arcgis.com/en/arcgis-online/reference/use-url-parameters.htm)). |
| QGIS Server | A map is requested with the WMS parameters `LAYERS`, `CRS`, `BBOX`, `WIDTH`, `HEIGHT` and the QGIS parameter `DPI` ([QGIS Server, WMS](https://docs.qgis.org/3.40/en/docs/server_manual/services/wms.html)). |
| OpenLayers | The example [Permalink](https://openlayers.org/en/latest/examples/permalink.html) writes `#map=zoom/x/y/rotation` in the fragment of the address. |
| Choices of Lynkeus | The state is written in the fragment of the address, which the browser does not send to the server: `#map=zoom/latitude/longitude`, as OpenStreetMap writes it, then `&rotation=` in degrees clockwise when the map is rotated, `&basemap=` with the name of the background map or the word `none`, `&imagery=` with the name of the layer of NASA GIBS and the day when the background map is the imagery of a date, and `&area=west,south,east,north` when an area is set. The zoom level has two decimals and the centre five, about one metre. The page reads the fragment when it opens and whenever the fragment changes, and then takes the parts of the link out of the address, so that the address never names a state other than the one shown. |
| Validation | A number must be written with digits only. The zoom level must lie inside the limits of the view, the centre inside Web Mercator (latitude up to 85.0511 degrees), the rotation between -360 and 360 degrees, the background map must be one that Lynkeus offers, the image of a date must be one of the four layers of NASA GIBS that Lynkeus offers, on a day between its first day and the present day, and the area must be a valid area. A part that fails is ignored and named in a warning; the other parts are applied. A part with an unknown name is ignored and stays in the address. |
| Limits | The link does not hold the layers of the map. Lynkeus keeps the layers of a session for that session only, so a link cannot show them to another person; the form says so. The link does not hold the open panes, the selected tab or the display of a layer. The zoom level is rounded to two decimals, so the scale of the opened map may differ by up to 0.35 per cent. |
| Clipboard | `Clipboard.writeText` is available only in a secure context (HTTPS) ([MDN](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard/writeText)). When the browser refuses the copy, the address is selected in its field, so that the keyboard can copy it. |
| Tried | The form showed `#map=8/42.775/-70.975&basemap=openstreetmap&area=-71.2,42.6,-70.75,42.95` after the address of the page. A page opened with this fragment showed that view, background map and area, and the fragment left the address. The fragment `#map=99/1/1&basemap=moon&area=5,5,1,1` gave the warning "The address of the page gives a view, a background map and an area that Lynkeus cannot read. These parts were ignored." The test address was not a secure context, so the browser refused the copy: the outcome was a warning, and the field had the focus with the whole address selected. A copy on a secure address was not tried. The parts `basemap=none` and `imagery=` were added afterwards and were not tried in a browser. |

## Layer

| | |
|---|---|
| Standard | A link with the attribute `download` saves a file of the same site under the name that the attribute gives ([MDN, the anchor element](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/a)). |
| Function used | The file of a layer is a Cloud-Optimised GeoTIFF that the server of Lynkeus already serves, at the address that the description of the layer gives. The browser asks the server for it and stores it as a download, so the file does not pass through the memory of the page, and the saved file is the file of the server, byte for byte. |
| Choices of Lynkeus | The file is named from the title of the layer and its dates: the title in lower-case letters and digits, without the dates that it ends with, then each date as eight digits, for example `backscatter-hh-20261021.tif`. The form of the name comes from no source. |
| Limits | The file is the data of the layer, not its picture: the colours and the range of the display are not in it. |
| Tried | Not tried in a browser. The tests cover the name and the link that is clicked. That the saved file equals the file of the server was not measured. |

## Record

| | |
|---|---|
| Record of Lynkeus | The server writes a STAC Item (STAC 1.1.0) beside the file of each layer, with the fields `processing:lineage`, `processing:datetime` and `processing:software` of the Processing extension (version 1.2.0), a link `via` to the granule in CMR for a received layer and links `derived_from` to the records of the inputs for a result (code of the part of Lynkeus that receives layers, read on 14 Nov 2026). The STAC specification itself was not read for this function. |
| Function used | The record is read from the site with `fetch` and saved as a file. |
| Choices of Lynkeus | The form offers two files. "STAC record" is the record as the server wrote it, with two changes that keep it valid beside the saved layer: the address of the data file becomes the name under which Lynkeus saves that file, and each link to another file of the site becomes a full address. "Provenance record" is a plain text: title, kind, quantity, unit, dates, input files, program, the reference of the method of a result, and the lineage, the time of processing and the software from the record. The files have the name of the saved layer, with `.json` and `-provenance.txt`. A record is read only from the site itself. |
| Tried | Not tried in a browser. The tests use records with the fields that the server writes. |

## Citation

| | |
|---|---|
| NASA Earthdata | The catalogue page of a NISAR collection gives its citation in the form "NASA/JPL/NISAR. (2026). *title* [Dataset]. NASA Alaska Satellite Facility Distributed Active Archive Center. https://doi.org/10.5067/NIL2GCOV-P1 Date Accessed: ..." (page of the provisional GCOV product, read through a search result, because the site refused the request of the server with HTTP 403). |

| Standard | The Scientific Citation extension of STAC, version 1.0.0. Its schema gives a record the fields `sci:doi` ("Data DOI", a text of the form `^10\.[0-9a-zA-Z]{4,}/[^\s]+$`, so without the address of the resolver) and `sci:citation` ("Proposed Data Citation"), and demands one of the fields of the extension in a record that declares it ([schema](https://stac-extensions.github.io/scientific/v1.0.0/schema.json)). The page that describes the extension in words was not read. |
| Function used | The citation of the data is read from the record of the layer: `sci:citation` word for word when the record has it, and otherwise a citation built from `sci:doi`. A result names no dataset itself; its record links to the records of its inputs with the relation `derived_from`, and these are read in turn, each dataset once. |
| Choices of Lynkeus | Without `sci:citation`, the citation has the form of the catalogue page, with the title that CMR gives for the DOI and without the year, because CMR does not state it: "NASA/JPL/NISAR. title [Dataset]. NASA Alaska Satellite Facility Distributed Active Archive Center. https://doi.org/...". "Date accessed" is the day on which Lynkeus received the data (`processing:datetime` of the record). The text then lists the product files, the reference of the method of a result, and Lynkeus with its version as software. A layer whose record names no DOI gets no citation: the button says so and cannot be used. At most 32 records are read for one layer; the number comes from no source. |
| Limits | The server does not yet write `sci:doi`, so the citation is not available for the layers of today. |
