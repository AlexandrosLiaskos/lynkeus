# Research note: Data tab, Catalog pane, server and frame of the page

This note records, for each function of this part, how GIS programs offer it, which existing function Lynkeus
uses for it, the limits found and what could not be confirmed. Every source was read on the date given.

## Description of a button

| | |
|---|---|
| ArcGIS Pro | A ScreenTip with information about the command appears when the pointer rests on a button of the ribbon ([Help within the application](https://doc.esri.com/en/arcgis-pro/latest/get-started/help-within-the-app.html)). A command has a `Tooltip`, a brief description, and a `DisabledTooltip`, a supplementary text that appears only when the command is disabled ([ArcGIS Pro SDK, MapTool class](https://doc.esri.com/en/arcgis-pro/latest/sdk/api-reference/topic9985.html)). |
| QGIS | Not read. |
| Standard | A tooltip is referenced by `aria-describedby` on the element that it describes, never receives focus and closes on the Escape key. It stays visible while the pointer is on it, as criterion 1.4.13 of the Web Content Accessibility Guidelines 2.1 asks ([MDN, ARIA: tooltip role](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Roles/tooltip_role)). |
| Function used | The component `Tooltip` in `web/src/shared/tooltip/`, with the colours of the U.S. Web Design System 3.14.0. The tooltip of the design system (`packages/usa-tooltip` in the npm package) was read and not used: its body is placed inside the wrapper of its trigger, and the panel of the ribbon scrolls sideways, which would cut a description that stands under a button. |
| Limits | A touch screen has no resting pointer, so the description reaches a touch user only through assistive technology. |
| Tried | Chromium, through Playwright 1.65.1: the description shows after the pointer rests on a button, stays when the pointer moves onto it, hides when the pointer leaves, after a click and on the Escape key, and shows at once on keyboard focus. |
| Read on | 14 Nov 2026 |

## Dialog

| | |
|---|---|
| Design system | The modal is labelled by its heading through `aria-labelledby`, keeps the keyboard focus inside it, and returns the focus to the element that opened it ([Modal](https://designsystem.digital.gov/components/modal/), [Modal accessibility tests](https://designsystem.digital.gov/components/modal/accessibility-tests/)). Since version 3.14.0 the focus moves, on opening, to the first enabled button of the footer ([release notes](https://github.com/uswds/uswds/releases)). |
| Function used | The `dialog` element of the browser, opened with `showModal()`, with the styles of the package `usa-modal` of the design system. `showModal()` displays the dialog in the top layer with a `::backdrop`, and the rest of the document becomes inert. It has been available in all main browsers since March 2022 ([MDN, HTMLDialogElement: showModal()](https://developer.mozilla.org/en-US/docs/Web/API/HTMLDialogElement/showModal)). |
| Read and not used | The script of the modal of the design system, which moves elements of the page and so cannot share them with React. The `Modal` of `@trussworks/react-uswds` 13.0.1 (type definitions and code of the npm package): it keeps its open state inside itself and offers no callback for closing, so the part that opened it cannot learn that the Escape key closed it. |
| Limits | The first focus goes to the heading of the dialog, not to the first button of the footer; [frame.md](frame.md) gives the reason. Between two rounds of the Tab key the focus passes once through the browser's own controls; no element of the page behind the dialog can take it. |
| Tried | Chromium, through Playwright 1.65.1: the Escape key, the close button and a click outside the dialog close it; the focus returns to the button that opened it; over 16 presses of the Tab key the focus was on an element of the dialog 14 times and on the browser's own controls twice. In the tests, happy-dom 21.0.4 provides `showModal()`; jsdom 31.0.1 does not. |
| Read on | 14 Nov 2026 |

## Messages

| | |
|---|---|
| QGIS | The message bar has four levels: Info, Warning, Critical and Success. A message takes a duration in seconds. A critical message must be dismissed by the user, and a message of information or success leaves after a default time ([QgsMessageBar](https://api.qgis.org/api/classQgsMessageBar.html), [PyQGIS Developer Cookbook, Communicating with the user](https://docs.qgis.org/3.40/en/docs/pyqgis_developer_cookbook/communicating.html)). |
| ArcGIS Pro | Not read. |
| Function used | The alert of the U.S. Web Design System 3.14.0 (package `usa-alert`), in its slim form, with the four kinds success, info, warning and error. An error carries the role `alert` and the other kinds the role `status`. |
| Limits | The alert of the design system has no close button; Lynkeus adds one. A message of success or a notice leaves after 8 seconds, which is a choice of Lynkeus and comes from no source. It stays while the pointer or the keyboard focus rests on it. |
| Tried | Chromium, through Playwright 1.65.1: the four kinds show with the icons of the design system; the close button removes one message; after 8.5 seconds the success and the notice had left, and the error and the warning remained. |
| Read on | 14 Nov 2026 |

## Pane frame

| | |
|---|---|
| ArcGIS Pro | The Contents and Catalog panes are open on either side of the map when the program is first opened. A pane can be closed, and the group Windows of the View tab opens the Contents and Catalog panes again and resets them ([Introduction to ArcGIS Pro](https://pro.arcgis.com/en/pro-app/3.4/get-started/get-started.htm)). A pane is resized by dragging one of its sides ([Introducing ArcGIS Pro](https://pro.arcgis.com/en/pro-app/3.2/get-started/introducing-arcgis-pro.htm)). |
| QGIS | Not read. |
| Standard | The edge that resizes a pane is a window splitter: an element with the role `separator` that can take focus, states its position in `aria-valuenow`, and moves with the arrow keys ([WAI-ARIA Authoring Practices 1.2, Window Splitter](https://www.w3.org/TR/2021/NOTE-wai-aria-practices-1.2-20211129/)). |
| Function used | The component `Pane` in `web/src/shared/pane/`. The edge that changes the width belongs to the side of the map on which the pane stands; [frame.md](frame.md) describes it with the stack of panes. |
| Limits | A pane keeps its side. It cannot float or hide by itself, as in ArcGIS Pro. In a window narrower than 1024 pixels both panes start closed. |
| Tried | Chromium, through Playwright 1.65.1, in a window of 1440 by 900 pixels: dragging the edge of the left pane by 100 pixels changed its width from 288 to 388 pixels, and `aria-valuenow` read 388; two presses of the left arrow key on the edge of the right pane changed its width from 288 to 320 pixels; after the right pane was closed the map took its place (width 732 to 1052 pixels). In a window of 390 pixels both panes were closed and the page did not scroll sideways. |

## Search of products

| | |
|---|---|
| Catalogue | NASA's Common Metadata Repository (CMR) holds one record for each NISAR product file. A search needs no Earthdata account. The collections were read from `https://cmr.earthdata.nasa.gov/search/collections.umm_json` (provider ASF, short name `NISAR_L*`): 31 collections. GCOV, GUNW and GOFF each have a validated, a provisional and a beta collection, and SME2 has a provisional and a beta collection. Their short names and identifiers are in `api/src/lynkeus/products.py`. The records of the validated and the provisional collections state 28 October 2025 as the first day of the data, and the records of the beta collections 1 October 2025. The earliest beta product starts on 12 October 2025 (GCOV) and the earliest provisional product on 29 October 2025. |
| Fields of a record | Read from the records of four product files (in `api/tests/data/`) and from the 400 latest and the 400 earliest records of each of the eleven collections (7,544 records, because three collections hold fewer than 800): the name (`GranuleUR`), the start and end of the acquisition (`TemporalExtent`), the outline (`SpatialExtent`, one or more polygons without holes), the kinds of surface and the continents (`GranuleLocalities`), the absolute orbit number (`OrbitCalculatedSpatialDomains`), the files with their sizes and checksums (`DataGranule`), the addresses of the files (`RelatedUrls`), the input products (`InputGranules`), the program (`PGEVersionClass`), and the additional attributes listed below. A product made from a pair of acquisitions (GUNW, GOFF) also carries the start and the end of each acquisition. No field holds the cycle; it stands in the name, after the product type ([naming convention of GCOV](https://nisar-docs.asf.alaska.edu/gcov/)). |
| Programs read | ASF Vertex ([manual](https://docs.asf.alaska.edu/vertex/manual/), [NISAR guide](https://nisar-docs.asf.alaska.edu/vertex/), [baseline tool](https://docs.asf.alaska.edu/vertex/baseline/)), the ASF search API and the library asf_search ([keywords](https://docs.asf.alaska.edu/api/keywords/), [searching](https://docs.asf.alaska.edu/asf_search/searching/), file `asf_search/CMR/field_map.py` of the [source](https://github.com/asfadmin/Discovery-asf_search), commit 7cfcfa8), NASA Earthdata Search ([NISAR guide](https://nisar-docs.asf.alaska.edu/earthdata-search/), [address parameters](https://wiki.earthdata.nasa.gov/display/EDSC/Earthdata+Search+URL+Parameters)), ArcGIS Pro ([processing extent](https://doc.esri.com/en/arcgis-pro/latest/help/analysis/geoprocessing/basics/extent-control.html), [extent setting](https://pro.arcgis.com/en/pro-app/latest/tool-reference/environment-settings/output-extent.htm), [catalog views](https://pro.arcgis.com/en/pro-app/latest/help/projects/use-catalog-views.htm), [search of portal items](https://pro.arcgis.com/en/pro-app/latest/help/projects/search-portal-items.htm)) and QGIS 3.44 ([extent parameter of a tool](https://docs.qgis.org/3.44/en/docs/user_manual/processing/toolbox.html), [spatial extent selector](https://docs.qgis.org/3.44/en/docs/user_manual/introduction/general_tools.html)). The pages were read as text; the programs themselves were not run. |
| Function used | earthaccess 0.19.0, class `DataGranules`: `concept_id`, `bounding_box`, `temporal`, `orbit_number`, `readable_granule_name` and `option` (code of the installed package). earthaccess has no function for additional attributes, for several polygons, for a season or for an offset, so Lynkeus writes these four into the `params` of the query in the form of the catalogue, and sends the query once with `page_size` and `offset`, as the function `hits` of earthaccess sends it. One answer carries the products and, in the header `CMR-Hits`, the number that match. The browse image is received with `http.client` of Python. In the interface: the tool pane of the frame (`shared/toolpane`), the interaction `Draw` of OpenLayers 10.11.0 with `createBox` and `freehand` for the rectangle, the function `getFeaturesAtCoordinate` of its vector source for the product under the pointer, its formats `GeoJSON` and `KML`, the function `simplify` of its geometries, and the function `DecompressionStream` of the browser for a zip file. |
| Choices of Lynkeus | A search without a choice of level reads the validated and the provisional collections. One answer holds 200 products, the list holds at most 2,000, and a search may take 45 seconds (one request to the catalogue 40 seconds). The period starts as the last 30 days, and the offered periods are 12, 30, 90 and 365 days and the whole mission, which starts on 1 October 2025, the earliest first day of a collection. The area is chosen in one list, as the extent of a tool in ArcGIS Pro and QGIS, and starts as the area drawn with the Map tab or, without one, the view of the map. The Catalog pane comes to the front only when a search finds products. "All dates of this frame" searches at the levels of validation of the list. Every product states the layers that Lynkeus receives, as `lynkeus.harmony.layers_of` lists them for its type and the channels of its main band. A product of a beta collection states the same layers as a validated one: NASA Harmony lists the same variables and the same service for the beta collections (read from `https://harmony.earthdata.nasa.gov/capabilities` on 15 Nov 2026), and no beta layer was received in a trial. The description of every layer states the level of validation of its product. A product whose record states only band B states none, because the layers are those of band A; this rule follows from the group `frequencyA` of the layers and was not tried with a request to Harmony. The polygons of an area are at most 10 with at most 250 points in all; a longer address is refused (measured below). A side of a drawn polygon receives a point every 2 degrees of longitude, because the catalogue joins two points along the shortest way on the globe and the map joins them with a straight line. Coordinates are sent with 5 decimals. A file with an area is at most 20 MB, and a file inside a zip file at most 50 MB. A search by names takes at most 50 names. Selecting a product moves the map to its outline when the map does not show it, or shows it narrower than one eighth of the view. A click on the map selects the first product under the pointer, and the next click on the same place the product after it. These numbers and rules come from no source. |
| Limits | The four product types of Lynkeus are searched; the catalogue also holds the raw, RSLC, GSLC, RIFG, RUNW and ROFF products. Channels and bands are joined with "and": a product is found when it has every channel chosen. Vertex instead offers the eight exact combinations of channels and the seven of bandwidths. The bandwidth is that of the main band. The cycle is read in the product name, and for a pair it is the cycle of the first acquisition. A name pattern that starts with a wildcard takes about 11 seconds. The order by size follows the sum of all files of a product, and the list shows the size of the product file alone. The holes of a polygon of a file are left out, because the catalogue takes polygons without holes. A polygon that encloses a pole is not handled. A shapefile must be in degrees on WGS 84; other systems are refused and not transformed. The reading of the zip and shapefile formats was written from the formats themselves, which were not read again on this date; it was checked with a shapefile written by pyshp 3.1.8 and zipped by Python 3.13. The days between the two dates of a pair cannot be searched in the catalogue; the list can be grouped by them. The browse image shown is the small one (100 by 100 pixels), which the server passes on because the page accepts images only from its own address; soil moisture products have none. |
| Tried in a browser | 14 Nov 2026, Chromium through Playwright 1.65.1, at 1440 by 900 pixels, on a private copy of the page and of the web service, which asked NASA's catalogue. The user ended the browser checks on private copies during this work, so the last run was stopped before its end. It ran on the code of this pull request before the first day of the whole mission moved from 28 to 1 October 2025. In it: the pane opened beside the map with the focus on its title; the search of the box (1 Oct to 14 Nov 2026) listed 12 GCOV products in 1.1 seconds and brought the Catalog pane to the front; the details showed the browse image (100 pixels wide) and 23 file links; the pointer on an outline marked one product of the list; a click on an outline selected a product and a second click on the same place the next one; the outlines were hidden and shown; the list was grouped by track and frame (4 groups of 3); the order "earliest first" asked the server again; the list was saved as CSV (13 lines) and as GeoJSON (12 features); "All dates of this frame" listed the 11 products of track 141, frame 67 and put its choices in the form; a rectangle and a polygon drawn on the map became the area, and the polygon found 19 products; the zipped shapefile, the KML and the GeoJSON file of the box each gave a polygon of 4 points, and its search listed the same 12 products; the outline of the selected product became the area (6 points); a GUNW pair of 9 and 21 October 2026 was found for the period 15 October alone, and not when both dates must lie inside the period. In the run before it, which ran to its end on the code before three later changes (the rectangle drawn with one drag, no message for a search that the Catalog pane starts and that finds products, no side padding of the link buttons), the page showed no message in its console and no request failed, and at 390 by 800 pixels the page did not scroll sideways and showed the 12 products and the details. |
| Not tried in a browser | The search with a season, channels, a bandwidth and a direction chosen in the form; the search by names; "Load 200 more"; "Zoom to all"; the area from a view of the map across the meridian of 180 degrees; the refusal of a wrong choice in the pane. No run reached these steps. They are covered by the tests of the interface, which run in a simulated browser, and by the rows below, which were asked through the functions of the server. Nothing was tried in a browser after the branch was moved onto the status bar, the tools of the Map tab, the later changes of the frame and the layers through Harmony, nor after the layers of a product were added and the explanations of the fields moved behind the buttons beside their titles. Firefox and Safari were not tried, nor a touch screen. |
| Read on | 14 Nov 2026 |

### Additional attributes of the NISAR records

Counted in the catalogue on 14 Nov 2026 over the validated, provisional and beta collections of each product type.

|---|---|---|

Every record lies in tracks 1 to 173 and frames 1 to 176, the numbers of the [track and frame database](https://nisar.asf.earthdatacloud.nasa.gov/NISAR-SAMPLE-DATA/DOCS/NISAR_D-105021_RevA_Track_Frame_Database_SIS_20250428_w-esig.pdf). | One number or a range |

| `FREQUENCY_A_POLARIZATION`, `FREQUENCY_B_POLARIZATION` | `HH`, `HV`, `VH`, `VV`; no record has `LH`, `LV`, `RH` or `RV`. Band B only in GCOV and SME2. | Channels of each band |
| `FREQUENCIES` | `A`, `B` or both; GUNW and GOFF only `A` | Frequency bands |
| `FREQUENCY_A_RANGE_BANDWIDTH` | 5, 20, 40, 77 (megahertz); not in SME2 | Bandwidth |
| `FREQUENCY_B_RANGE_BANDWIDTH` | 5 | Shown in the details |
| `FULL_FRAME` | `TRUE`, `FALSE` | Coverage of the frame |
| `JOINT_OBSERVATION` | `TRUE`, `FALSE` | Observed with the S-band radar |
| `REFERENCE_ZERO_DOPPLER_START_TIME`, `SECONDARY_ZERO_DOPPLER_START_TIME` | Moments, in GUNW and GOFF. In 4,000 records read the first acquisition is always before the second, the period of the record runs from the start of the first to the end of the second, and the days between are 12, 24, 36, 48, 60 or 72. | Both dates inside the period |
| `STACK_ID` | For example `141_D_067`: track, direction, frame | Through track, frame and direction |
| `PRODUCTION_PIPELINE`, `PROCESSING_CENTER`, `ORBIT_TYPE` | `PR`, `JPL`, `MOE` in every record read | Not offered: one value |
| `PRODUCT_VERSION`, `PRODUCT_TYPE`, `PRODUCT_TYPE_DESC`, `PROCESSING_LEVEL`, `RANGE_BANDWIDTH_CONCAT`, `FREQUENCY_A_POLARIZATION_CONCAT`, `FREQUENCY_B_POLARIZATION_CONCAT` | Text | Shown in the details |

## Server: sessions, processes and jobs

| Standard | [OGC API - Processes - Part 1: Core](https://docs.ogc.org/is/18-062r2/18-062r2.html) (OGC 18-062r2, version 1.0.0) and its [schemas](https://schemas.opengis.net/ogcapi/processes/part1/1.0/openapi/schemas/). Every process is executed asynchronously, so a request is answered with 201, the header `Location` and the state of the new job (requirement 34). A process has one output, the layer description, given by value. For a request without the field `response` the results are the layer description itself (requirement 39). For `"response": "document"` they are `{"layer": {"value": ...}}`, because `results.yaml` takes an object only inside a qualified value. An error carries the exception type that the standard names (requirements 15, 37, 44 and 45) in the problem details of RFC 7807 (recommendation 3). A job is dismissed once with 200 and its address then answers 410 (clause III.C). |
| Inputs | The schema of an input is the schema object of OpenAPI 3.0 (`schema.yaml`). The inputs of a process are declared as a pydantic format, and its JSON Schema is converted to that form: a reference is replaced by its definition, `const` becomes `enum`, a choice with `null` becomes `nullable`, and the items of a tuple become `items`. The same format checks the inputs of a request (requirements 24 and 49). An input value is taken plain, as a qualified value (requirement 20), as a bounding box (requirement 23), as a base64-encoded string for a binary value (requirements 22 and 50) and as a link. Requirement 18, part B, obliges every server to take an input value given as a link: "The server SHALL support process input values specified by reference". The server then reads an address that the visitor chose, so `lynkeus.references` reads a link only over HTTPS, looks the host name up once, refuses the link when one of its addresses is not public (loopback, private, link-local, shared, reserved, multicast, in IPv4 and IPv6, also inside an IPv4-mapped, 6to4 or Teredo address), connects to the address that it checked, follows no redirect, and takes JSON of at most 65,536 bytes within 10 seconds, for at most 8 links in one request. |

[Cookies: HTTP State Management Mechanism](https://datatracker.ietf.org/doc/draft-ietf-httpbis-rfc6265bis/) (draft 22 of 1 December 2025, in the queue of the RFC Editor on the day read): the syntax of the attributes, and the limit of 400 days on the age of a cookie. |
| Earthdata token | [User Token Management](https://urs.earthdata.nasa.gov/documentation/for_users/user_token) of Earthdata Login (last updated 1 July 2026): a user token is valid for 60 days and a user holds at most two. | Function used | FastAPI routes in `lynkeus.routes`. `sqlite3` of the standard library for the record of sessions, jobs and layers. `multiprocessing` with the start method `spawn` for the operating-system process of a job, which leads a process group of its own; the group receives `SIGTERM` and, 5 seconds later, `SIGKILL`. `secrets` for the keys and names. | Choices of Lynkeus | These numbers come from no source. Earthdata token: forgotten after 30 minutes without a request of the session and after 8 hours at the latest (the two upper values of OWASP). ## Server: the processes offered

| | |
|---|---|
| Standard | [OGC API - Processes - Part 1: Core](https://docs.ogc.org/is/18-062r2/18-062r2.html). The summary of a process carries `id`, `version`, `title`, `description`, `jobControlOptions` and `outputTransmission` ([`processSummary.yaml`](https://schemas.opengis.net/ogcapi/processes/part1/1.0/openapi/schemas/processSummary.yaml)). It may carry `additionalParameters`, whose field `parameters` is a list of entries with a `name` and a list `value` ([`descriptionType.yaml`](https://schemas.opengis.net/ogcapi/processes/part1/1.0/openapi/schemas/descriptionType.yaml), [`additionalParameter.yaml`](https://schemas.opengis.net/ogcapi/processes/part1/1.0/openapi/schemas/additionalParameter.yaml)). The process `get-layer` gives the largest number of cells of a layer there, under the name `most-cells`, so that the interface reads the limit from the server. |
| Processes | `lynkeus.offered` lists the processes and `lynkeus.server` installs the list. **`get-layer`** takes a layer request (product type, name of the product file, name of the layer, area) and needs the sign-in to Earthdata. Its function calls `lynkeus.harmony.get_layer` with the token of the visitor. **One process for every analysis tool** of `lynkeus.analysis.TOOLS`, under the name of the tool. It takes the `id` of each input layer and the name of the result, needs no sign-in, and its function calls `lynkeus.tools.run_tool`. The list is made when the web service starts, so a tool that enters `TOOLS` is offered without a change in the server. Both kinds name `lynkeus.writing.LayerError` as the error whose sentence is for the visitor, so the sentence becomes the message of the failed job. |
| What an analysis tool provides | **Name.** Its name in `TOOLS`, in lower-case letters, digits and hyphens, is the name of the process and of the two files of a result. With spaces for its hyphens it is the title of the process: `backscatter-change` gives "Backscatter change". **Documentation string.** The first paragraph of the documentation string of its function is the description of the process, so it states in one or two sentences what the tool computes. **Errors.** For layers that the tool cannot use, for example a wrong number of layers, the function raises `lynkeus.writing.LayerError` with one sentence for the visitor. Any other error reaches the visitor as "Lynkeus could not compute the result because of an internal error." A tool with a wrong name or without a documentation string stops the start of the web service, and a test of the server fails for it first. |
| Functions used | `functools.partial` joins the name of a tool to the function of its process. The job receives the function through `pickle`, and `lynkeus.processes.Process` refuses a function that `pickle` cannot send. Python runs a signal handler in the main thread, and only the main thread can set one ([signal](https://docs.python.org/3/library/signal.html)). harmony-py 1.8.0 prints the path of each file that it fetches when the environment variable `VERBOSE` is absent or `TRUE` (method `_download_file` in `harmony/client.py`, code of the package read). `mem_limit` in a Compose file "configures a limit on the amount of memory a container can allocate" ([Compose file reference, services](https://docs.docker.com/reference/compose-file/services/)). |
| What the functions of the layers need from a job | **The main thread.** `lynkeus.harmony` sets a handler for the signal SIGTERM that cancels the job of Harmony. A job calls the function of its process in the main thread of its operating-system process, so the handler is set and runs. **No folder left behind.** A job that fails, is dismissed, passes a limit or is ended by a stop of the server can leave the folder of Harmony's file or a plain copy of the layer in its folder. `lynkeus.jobs` removes the folder of every job that kept no layer, and at the next start every folder that belongs to no layer. **A real disk.** `compose.yaml` mounts the folder `data/api` of the machine at `/data`, and a job writes under `/data/files`. By the sizes of the trial of the backscatter layer (4.9 bytes a cell in the file of Harmony and 3.5 in the file of Lynkeus), the largest layer of 25 million cells needs about 122 MB for the file of Harmony, which is removed before the layer is written, and then 100 MB for the plain copy and about 87 MB for the layer. Both sums are below the 500 MB at which a job is ended. **No path in the log.** The function of `get-layer` sets `VERBOSE` to `FALSE` in the job, because the output of a job is the log of the server and the path names the folder of the layer. **A connection to NASA.** The network of the containers is a bridge network that is not internal (`docker network inspect`), and the product search of the site already reaches NASA's catalogue from the same container. |
| Memory | Measured before this change: the web service held 47 to 71 MiB without jobs, the job that received the backscatter layer of 15.0 million cells 390 MB at most, and the writing of a layer 353 MB for 15.0 million cells and 508 MB for 25 million, the largest layer. The list of processes makes the service import Rasterio and harmony-py, which adds about 27 MiB (under Tried). Two jobs run at once, so the service and two jobs of the largest layer hold about 71 + 27 + 2 × 508 = 1,114 MB, more than the 1,024 MB that the container was allowed. **Choice.** The container is allowed 2 GB (2,048 MB) and two jobs still run at once. A job that receives a layer waits for Harmony for most of its time (275 of 297 s in the trial of the backscatter layer), so one job at a time would double the wait of a visitor who asks for the layers of two dates. The machine has 7,940 MB and no swap space; on 14 Nov 2026 at 17:32 UTC it had 4,837 MB available with all its other sites running (`free -m`). The limit leaves about 930 MB above the service and two jobs of the largest layer. A job of a tool holds the values of each input layer and of the result, 100 MB each for the largest layer, before it writes the result; no tool is finished, so no job of a tool was measured. |
| Time | Lynkeus waits for a job of Harmony for at most 30 minutes (`MOST_WAIT` in `lynkeus.harmony`) and then fails with a sentence about Harmony. A job of Lynkeus was ended after the same 30 minutes, counted from its start, so its own limit always came first, also for a job that was fetching or writing its layer. A job may now run for 40 minutes. In the trial of the backscatter layer the steps outside the wait for Harmony took 22 s. |
| Choices of Lynkeus | These numbers and forms come from no source. The memory limit of 2 GB. The 10 minutes that a job has beyond the wait for Harmony. A tool takes at most 50 input layers, the number that a session holds, and each layer once. The name of a result has at most 200 characters, as the title of a layer. The title of the process of a tool is its name with spaces. A job of `get-layer` is named by the layer and the product file, for example "Backscatter HH of NISAR_L2_PR_GCOV_…", and a job of a tool by the name of its result. |

## Layers through Harmony and the files of Lynkeus

| | |
|---|---|
| NASA Harmony | Harmony clips one layer of a NISAR product file to a box of longitude and latitude and returns it as a GeoTIFF, through the service `nasa/harmony-gdal-adapter`. Its capabilities (`https://harmony.earthdata.nasa.gov/capabilities?collectionId=<collection>`) list the layers that it can deliver for each collection: 20 for GCOV, 23 for GUNW, 43 for GOFF and 13 for SME2, the same for the validated and the provisional collection of a type. The lists are in `api/tests/data/harmony-variables.json`. The file keeps the projection and the cell size of the product, and its cells outside the box hold no data. A licence agreement that is not accepted gives an error when the request is submitted ([Earthdata Cloud Cookbook, harmony-py tutorial](https://pommevilla.github.io/earthdata-cloud-cookbook/transformations/HarmonyPy_intro_tutorial.html)). |
| Product specifications | The names, quantities and units of the layers come from the NISAR product specifications, which the [NISAR Data User Guide](https://nisar-docs.asf.alaska.edu/product-specification/) lists. The revisions read are GCOV, JPL D-102274, revision F (8 July 2026); GUNW, JPL D-102272, revision E (8 Nov 2024); GOFF, JPL D-105010, revision C (8 Nov 2024); SME2, JPL D-107677, revision C (8 Nov 2024). GCOV: the terms of the covariance matrix are normalized to gamma nought by radiometric terrain correction, a diagonal term (`HHHH`, `HVHV`, `VHVH`, `VVVV`) is the backscatter of one channel, the layer `rtcGammaToSigmaFactor` turns gamma nought into sigma nought, and the cell size is 10, 20 or 80 m with the range bandwidth (table 2-3, sections 4 and 4.3.1). The values are linear: the product file of 21 Oct 2026 gives `10*log10(<GCOV_TERM>)` as the conversion to decibels (field `outputBackscatterDecibelConversionFormula`). GUNW: the wrapped interferogram and its coherence are at 20 m, and the unwrapped phase (radians), its coherence, the connected components, the ionosphere phase screen and the pixel offsets (metres) are at 80 m. GOFF: the pixel offsets are at 80 m in three offset layers, numbered from the finest resolution (`layer1`) to the coarsest (`layer3`). SME2: soil moisture in cubic metres of water in a cubic metre of soil, on the EASE-Grid 2.0 at 200 m, with -9999 in a cell without data. |
| Standards of the files | STAC 1.1.0, [Item specification and common metadata](https://github.com/radiantearth/stac-spec/tree/v1.1.0): `datetime` may be null when `start_datetime` and `end_datetime` are given; a band carries `data_type`, `nodata` (a number or the text `nan`), `unit` (UCUM or UDUNITS-2 is strongly recommended) and `statistics`; the link `via` leads to the record that is not STAC from which an Item was made. Extensions [projection 2.0.0](https://github.com/stac-extensions/projection/tree/v2.0.0) (`proj:code`, `proj:wkt2`, `proj:shape`, `proj:transform`, `proj:bbox`), [raster 2.0.0](https://github.com/stac-extensions/raster/tree/v2.0.0) (`raster:sampling`, `raster:spatial_resolution`) and [processing 1.2.0](https://github.com/stac-extensions/processing/tree/v1.2.0) (`processing:lineage`, `processing:level`, `processing:datetime`, `processing:software`, and the link `derived_from` to the Item of an input). Cloud Optimized GeoTIFF: the [COG driver of GDAL](https://gdal.org/drivers/raster/cog.html) writes tiles of 512 cells by default and reduced copies (overviews) until the smallest is not larger than a tile, and it takes the resampling of the reduced copies and the predictor of the compression as options. |
| GIS programs | QGIS: the stretch "Cumulative count cut" removes outliers, and its standard range is 2 % to 98 % ([QGIS user manual, Raster Properties](https://doc.qgis.org/testing/en/docs/user_manual/working_with_raster/raster_properties.html)). ArcGIS Pro: not read. |
| Colour scales | Matplotlib, [Choosing Colormaps](https://matplotlib.org/stable/users/explain/colors/colormaps.html): a sequential scale suits a quantity that has an order (`viridis` is perceptually uniform; `YlGnBu` and `gray` are sequential), a diverging scale suits a quantity with a middle value such as zero (`RdBu`), and a qualitative scale suits classes without order (`tab10`). |
| Function used | harmony-py 1.8.0 (code of the installed package read): `Client(token=...)` signs each request with the token; `Client()` takes the credentials of the environment and checks them with Earthdata Login; `submit` returns the identifier of a job, `status` its state, progress and message, `cancel` cancels it, and `result_urls` and `download` fetch the result. It asks for a job in every case (`forceAsync=true`), and it removes the token from a request that is redirected to a host other than Earthdata Login. Rasterio 1.5.2 with GDAL 3.12.2 reads and writes the GeoTIFF files; in the image `python:3.13-slim` it needs the system library `libexpat1`. In the tests, `cog_validate` of rio-cogeo 7.0.4 checks the files in strict mode, and jsonschema 4.26.0 checks the records against the published schemas, which are kept in `api/tests/data/stac/`. |
| Layers | The table below lists the layers that `layers_of` offers. The name of a layer is its path in the product inside the group of the main frequency band (`/science/LSAR/<type>/grids/frequencyA/`; for SME2 `/science/LSAR/SME2/grids/`). Every layer of the table was received from Harmony on real data before it was listed, for the channels named under "Tried on real data". `layers_of` gives each layer with its smallest cell size, so that the interface can estimate the cells of an area with the same rule as the server. |
| Choices of Lynkeus | **File.** 32-bit real numbers, `nan` in a cell without data whichever value the product uses, tiles of 512 cells, DEFLATE compression with the floating-point predictor. On the backscatter of 21 Oct 2026 (15.0 million cells; 73.2 MB as Harmony delivers it, with LZW) the sizes were: LZW 71.5 MB, DEFLATE 59.0 MB, DEFLATE with the floating-point predictor 52.0 MB (written in 3.6 s), the same at level 9 51.0 MB (14.4 s), ZSTD with the predictor 50.9 MB, LERC without loss 76.2 MB, no compression 89.1 MB. DEFLATE was taken over ZSTD, which is 2 % smaller, because it is the older of the two in TIFF files and more readers decode it; this reason comes from no source. **Reduced copies.** Lynkeus makes them from the values at full resolution and never passes on those of Harmony: by averaging for a quantity (the average of a power is taken on the linear values, and a cell without data is left out), and by the most frequent value for classes. **Legend.** Three rules give the range from the values: the 2nd and the 98th percentile (the standard of QGIS); for a quantity with a sign, the 98th percentile of the absolute values on both sides of zero; for classes, the lowest and the highest value. Coherence and the correlation peak, which lie between 0 and 1 by definition, keep that range. When a rule gives one value twice, the range is the lowest and the highest value, and for a layer of one value it runs from half a unit below to half a unit above it. **Colour scales.** The names are those of Matplotlib, with `grey` for its `gray`: `grey` for backscatter and coherence, `RdBu` for the quantities with a sign, `YlGnBu` for soil moisture, `viridis` for the other quantities and `tab10` for classes. The class of each scale follows Matplotlib; the choice of grey for radar images and of `YlGnBu` for soil moisture comes from no source. **Units.** As the CF conventions write them: `1`, `rad`, `m`, `m3 m-3`. **Record.** The description of a layer holds days, so the record gives the period from the start of the first day to the end of the last one and leaves `datetime` null. It has no `self` link, because the files do not know the address of the site. **Limits of size and time.** A layer has at most 25 million cells: the process that writes one used at most 353 MB of memory for 15.0 million cells and 508 MB for 25 million, in a container limited to 1 GB. The size is estimated before the request from the area and the smallest cell size of the layer, and counted again on the file received. Lynkeus waits for a job of Harmony at most 30 minutes, asks for its state every 3 seconds, as harmony-py does, and gives up after three questions in a row without an answer. The progress of a job of Harmony fills the part from 5 to 80 of the progress of a layer. These numbers come from no source. |
| Limits | Only the main frequency band is offered. Harmony lists no term of the compact channels RH and RV, and the terms outside the diagonal of the covariance matrix are not offered: the product files tried do not hold them. The complex wrapped interferogram is not offered, because the files of Lynkeus hold real numbers. The masks of GUNW and GOFF and the quality flags of SME2 are not offered: they are fields of bits, the mask of GUNW holds values up to 16,777,327, which a 32-bit real number does not keep exactly, and a legend of classes does not describe bits. The variances of the offsets of GOFF and the backscatter and incidence angle layers of SME2 were not tried and are not offered. The convention of the backscatter (gamma nought) is taken from the specification and is not read from each product file. The size of an area is estimated with the smallest cell size of the layer, so an area of a GCOV product with cells of 20 m is refused at a quarter of the surface that the limit of cells would allow. An area cannot cross the meridian of 180 degrees. A process that is ended while it waits between two questions cancels the job of Harmony within 3 seconds; a process that is killed (SIGKILL) cannot cancel it. Lynkeus sets no time limit on a single request to Harmony, so a connection that stays open without an answer ends only with the process. |

| Choices of Lynkeus | The state of the jobs is read every 3 seconds while a job waits or runs and the page is shown: one request for the whole list, which is 20 requests a minute where the web server accepts 120 a minute from one address. After a reading without an answer the pause doubles, up to 30 seconds. One reading follows at most 20 pages of the list. No layer of a product is chosen in advance. The area is the area of the search, shared in both directions, so that a layer is clipped to the area in which its product was searched; an area of polygons gives the rectangle around them, while the polygons themselves, not that rectangle, are compared with the outline of the product. With a job or a layer in it, the Catalog pane scrolls as a whole, and each of its sections is at most 20 rem high, above which its list scrolls. The states are written as Waiting, Running, Finished, Failed and Cancelled. The commands of an item stand as buttons under the item when it is clicked, because the context menu of a web page belongs to the browser. A layer is written as 32-bit numbers, so the estimate counts 4 bytes for a cell. These numbers and choices come from no source. |
| Limits | The area is a rectangle that does not cross the meridian of 180 degrees, as the layer request of the server takes it; the form refuses the whole Earth and a rectangle across that meridian. The form takes one product, because the list of the search selects one. The estimate is the largest number of cells that the area can hold and their size before compression, because the server states the smallest cell size that the product specification gives for a layer. It is given only for a layer whose cell size the server states; the limit on the cells of a layer is checked in the form only when the server states it. The surface is computed on a sphere of the mean radius of the Earth. The interface does not state when the server removes the jobs and the layers of a session. A job that ended while the page was closed is not announced, and its layer is not added to the map. The records of many finished jobs are removed one request after the other, so the web server may refuse a part of them when they are more than its limit of requests allows. |
| Tried on real data | The interface sent no request to NASA or to the real web service. The server side of the flow was tried on the live site with a real token of Earthdata Login, with requests sent apart from this form: the answer 401 without a sign-in, then a job accepted, running and successful after 274 seconds, the layer listed, its file served on a range request, and the layer removed. The tests of the interface use the record of a real product file (`api/tests/data/product-gcov.json`, GCOV, track 141, frame 67, 21 Oct 2026). For the box -71.20, 42.60, -70.75, 42.95 the form finds the area inside the outline of this product, a surface of 1,429 km² and, for a layer with cells of 10 metres, at most 14 million cells and 57 MB before compression. For the rectangle around the whole outline it finds 99,654 km² and at most 997 million cells. |
| Comparison | The surface on the sphere was compared with the surface on the WGS 84 ellipsoid, computed apart with the closed formula of the authalic latitude, which gives 510,065,622 km² for the whole Earth. The sphere gives 1,429.43 km² where the ellipsoid gives 1,431.87 km² for the box above (0.17 % less), 12,363.72 against 12,308.46 km² for one degree by one degree at the equator (0.45 % more), and 4,330.03 against 4,361.76 km² for one degree by one degree between 69 and 70 degrees north (0.73 % less). The server estimates the cells with the same formula and radius as the form. |
