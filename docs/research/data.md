# Research note: Data tab, Catalog pane, server and frame of the page

This note records, for each function of this part, how GIS programs offer it, which existing function Lynkeus
uses for it, the limits found and what could not be confirmed. Every source was read on the date given.

## Description of a button

| | |
|---|---|
| ArcGIS Pro | A ScreenTip with information about the command appears when the pointer rests on a button of the ribbon ([Help within the application](https://doc.esri.com/en/arcgis-pro/latest/get-started/help-within-the-app.html)). A command has a `Tooltip`, a brief description, and a `DisabledTooltip`, a supplementary text that appears only when the command is disabled ([ArcGIS Pro SDK, MapTool class](https://doc.esri.com/en/arcgis-pro/latest/sdk/api-reference/topic9985.html)). |
| QGIS | Not read. |
| Standard | A tooltip is referenced by `aria-describedby` on the element that it describes, never receives focus and closes on the Escape key. It stays visible while the pointer is on it, as criterion 1.4.13 of the Web Content Accessibility Guidelines 2.1 asks ([MDN, ARIA: tooltip role](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Roles/tooltip_role)). |
| Function used | The component `Tooltip` in `web/src/shared/tooltip/`, with the colours of the U.S. Web Design System 3.14.0. The tooltip of the design system (`packages/usa-tooltip` in the npm package) was read and not used: its body is placed inside the wrapper of its trigger, and the panel of the ribbon scrolls sideways, which would cut a description that stands under a button. |
| Limits | A touch screen has no resting pointer, so the description reaches a touch user only through assistive technology. |
| Tried | Chromium, through Playwright 1.65.1: the description shows after the pointer rests on a button, stays when the pointer moves onto it, hides when the pointer leaves, after a click and on the Escape key, and shows at once on keyboard focus. |
| Read on | 14 Nov 2026 |

## Dialog

| | |
|---|---|
| Design system | The modal is labelled by its heading through `aria-labelledby`, keeps the keyboard focus inside it, and returns the focus to the element that opened it ([Modal](https://designsystem.digital.gov/components/modal/), [Modal accessibility tests](https://designsystem.digital.gov/components/modal/accessibility-tests/)). Since version 3.14.0 the focus moves, on opening, to the first enabled button of the footer ([release notes](https://github.com/uswds/uswds/releases)). |
| Function used | The `dialog` element of the browser, opened with `showModal()`, with the styles of the package `usa-modal` of the design system. `showModal()` displays the dialog in the top layer with a `::backdrop`, and the rest of the document becomes inert. It has been available in all main browsers since March 2022 ([MDN, HTMLDialogElement: showModal()](https://developer.mozilla.org/en-US/docs/Web/API/HTMLDialogElement/showModal)). |
| Read and not used | The script of the modal of the design system, which moves elements of the page and so cannot share them with React. The `Modal` of `@trussworks/react-uswds` 13.0.1 (type definitions and code of the npm package): it keeps its open state inside itself and offers no callback for closing, so the part that opened it cannot learn that the Escape key closed it. |
| Limits | The first focus goes to the heading of the dialog, not to the first button of the footer; [frame.md](frame.md) gives the reason. Between two rounds of the Tab key the focus passes once through the browser's own controls; no element of the page behind the dialog can take it. |
| Tried | Chromium, through Playwright 1.65.1: the Escape key, the close button and a click outside the dialog close it; the focus returns to the button that opened it; over 16 presses of the Tab key the focus was on an element of the dialog 14 times and on the browser's own controls twice. In the tests, happy-dom 21.0.4 provides `showModal()`; jsdom 31.0.1 does not. |

## Messages

| | |
|---|---|
| QGIS | The message bar has four levels: Info, Warning, Critical and Success. A message takes a duration in seconds. A critical message must be dismissed by the user, and a message of information or success leaves after a default time ([QgsMessageBar](https://api.qgis.org/api/classQgsMessageBar.html), [PyQGIS Developer Cookbook, Communicating with the user](https://docs.qgis.org/3.40/en/docs/pyqgis_developer_cookbook/communicating.html)). |
| ArcGIS Pro | Not read. |
| Function used | The alert of the U.S. Web Design System 3.14.0 (package `usa-alert`), in its slim form, with the four kinds success, info, warning and error. An error carries the role `alert` and the other kinds the role `status`. |
| Limits | The alert of the design system has no close button; Lynkeus adds one. A message of success or a notice leaves after 8 seconds, which is a choice of Lynkeus and comes from no source. It stays while the pointer or the keyboard focus rests on it. |
| Tried | Chromium, through Playwright 1.65.1: the four kinds show with the icons of the design system; the close button removes one message; after 8.5 seconds the success and the notice had left, and the error and the warning remained. |

## Pane frame

| | |
|---|---|
| ArcGIS Pro | The Contents and Catalog panes are open on either side of the map when the program is first opened. A pane can be closed, and the group Windows of the View tab opens the Contents and Catalog panes again and resets them ([Introduction to ArcGIS Pro](https://pro.arcgis.com/en/pro-app/3.4/get-started/get-started.htm)). A pane is resized by dragging one of its sides ([Introducing ArcGIS Pro](https://pro.arcgis.com/en/pro-app/3.2/get-started/introducing-arcgis-pro.htm)). |
| QGIS | Not read. |
| Standard | The edge that resizes a pane is a window splitter: an element with the role `separator` that can take focus, states its position in `aria-valuenow`, and moves with the arrow keys ([WAI-ARIA Authoring Practices 1.2, Window Splitter](https://www.w3.org/TR/2021/NOTE-wai-aria-practices-1.2-20211129/)). |
| Function used | The component `Pane` in `web/src/shared/pane/`. The edge that changes the width belongs to the side of the map on which the pane stands; [frame.md](frame.md) describes it with the stack of panes. |
| Limits | A pane keeps its side. It cannot float or hide by itself, as in ArcGIS Pro. In a window narrower than 1024 pixels both panes start closed. |
| Tried | Chromium, through Playwright 1.65.1, in a window of 1440 by 900 pixels: dragging the edge of the left pane by 100 pixels changed its width from 288 to 388 pixels, and `aria-valuenow` read 388; two presses of the left arrow key on the edge of the right pane changed its width from 288 to 320 pixels; after the right pane was closed the map took its place (width 732 to 1052 pixels). In a window of 390 pixels both panes were closed and the page did not scroll sideways. |

## Search of products

| | |
|---|---|
| Catalogue | NASA's Common Metadata Repository (CMR) holds one record for each NISAR product file. A search needs no Earthdata account. The collections were read from `https://cmr.earthdata.nasa.gov/search/collections.umm_json` (provider ASF, short name `NISAR_L*`): GCOV, GUNW and GOFF each have a validated, a provisional and a beta collection, and SME2 has a provisional and a beta collection. Their short names and identifiers are in `api/src/lynkeus/products.py`. |
| Fields of a record | Read from the records of three product files (in `api/tests/data/`): the name (`GranuleUR`), the start and end of the acquisition (`TemporalExtent`), the outline (`SpatialExtent`, one or more polygons), the size of each file (`DataGranule`), and the additional attributes `TRACK_NUMBER`, `FRAME_NUMBER`, `ASCENDING_DESCENDING`, `FREQUENCY_A_POLARIZATION`. A product made from a pair of acquisitions (GUNW, GOFF) also carries `REFERENCE_ZERO_DOPPLER_START_TIME` and `SECONDARY_ZERO_DOPPLER_START_TIME`. |
| GIS programs | ArcGIS Pro and QGIS were not read for this function. NASA's own search pages (Earthdata Search, ASF Vertex) were not read. |
| Function used | earthaccess 0.19.0, class `DataGranules`: `concept_id`, `bounding_box`, `temporal`, `sort_key`, `hits` and `get` (signatures and documentation strings read from the installed package). The web service is FastAPI 0.162.7, run by Uvicorn 0.54.0; pydantic checks the choices of a search before the catalogue is asked. |
| Choices of Lynkeus | The validated and the provisional collection of a product type are searched together, and the list states which one holds each product. The beta collections are not searched. One search returns at most 200 products, the latest first, and states how many the catalogue holds. A search may take 45 seconds. The period starts as the last 30 days. Selecting a product moves the map to its outline when the map does not show it, or shows it narrower than one eighth of the view. These numbers come from no source. |
| Limits | An area cannot cross the meridian of 180 degrees. The catalogue gives the outline of a product that crosses it as two polygons, and Lynkeus draws both. The channels listed are those of the main frequency band (A). |
| Tried on real data | 14 Nov 2026. For the box -71.20, 42.60, -70.75, 42.95 and the period 1 Oct to 14 Nov 2026 the search returned 12 GCOV products (5 validated, 7 provisional) in 0.7 to 1.0 seconds, among them the two validated products of track 141, frame 67 (21 Oct and 2 Nov 2026). For the same box from 1 Sept 2026 it returned 18 GUNW and 13 SME2 products. For the whole Earth it reported 13,172 GOFF products and returned 200. The records of the latest 600 products of each of the seven collections (3,172 records) were all read without a fault; 25 of them have two polygons. |
| Tried in a browser | Chromium, through Playwright 1.65.1, on a private copy of the page and the web service: the search of the box above listed the 12 products, drew their outlines, reported "12 products were found." and opened the Catalog pane; a wrong latitude was refused in the dialog and nothing was sent; a search of GUNW over the whole view reported that the latest 200 of 35,133 products are listed; the outlines stayed on the map when the background map changed. |

## Server: sessions, processes and jobs

| | |
|---|---|
| Standard | [OGC API - Processes - Part 1: Core](https://docs.ogc.org/is/18-062r2/18-062r2.html) (OGC 18-062r2, version 1.0.0) and its [schemas](https://schemas.opengis.net/ogcapi/processes/part1/1.0/openapi/schemas/). The server implements the requirement classes Core, JSON, OGC Process Description, Job list and Dismiss, and declares these five at `/api/conformance`. It does not implement the classes HTML, OpenAPI 3.0 and Callback. Every process is executed asynchronously, so a request is answered with 201, the header `Location` and the state of the new job (requirement 34). A process has one output, the layer description, given by value. For a request without the field `response` the results are the layer description itself (requirement 39). For `"response": "document"` they are `{"layer": {"value": ...}}`, because `results.yaml` takes an object only inside a qualified value. An error carries the exception type that the standard names (requirements 15, 37, 44 and 45) in the problem details of RFC 7807 (recommendation 3). A job is dismissed once with 200 and its address then answers 410 (clause III.C). |
| Inputs | The schema of an input is the schema object of OpenAPI 3.0 (`schema.yaml`). The inputs of a process are declared as a pydantic format, and its JSON Schema is converted to that form: a reference is replaced by its definition, `const` becomes `enum`, a choice with `null` becomes `nullable`, and the items of a tuple become `items`. The same format checks the inputs of a request (requirements 24 and 49). An input value is taken plain, as a qualified value (requirement 20), as a bounding box (requirement 23), as a base64-encoded string for a binary value (requirements 22 and 50) and as a link. Requirement 18, part B, obliges every server to take an input value given as a link: "The server SHALL support process input values specified by reference". The server then reads an address that the visitor chose, so `lynkeus.references` reads a link only over HTTPS, looks the host name up once, refuses the link when one of its addresses is not public (loopback, private, link-local, shared, reserved, multicast, in IPv4 and IPv6, also inside an IPv4-mapped, 6to4 or Teredo address), connects to the address that it checked, follows no redirect, and takes JSON of at most 65,536 bytes within 10 seconds, for at most 8 links in one request. |
| Session | [Session Management Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html) of OWASP: an identifier of at least 64 bits from a secure random generator, without meaning; the cookie attributes `Secure`, `HttpOnly` and `SameSite`; a new identifier after every change of privilege; a limit on the time without use (15 to 30 minutes for an application of low risk) and on the whole time (4 to 8 hours for a working day). [Cookies: HTTP State Management Mechanism](https://datatracker.ietf.org/doc/draft-ietf-httpbis-rfc6265bis/) (draft 22 of 1 December 2025, in the queue of the RFC Editor on the day read): the syntax of the attributes, and the limit of 400 days on the age of a cookie. |
| Earthdata token | [User Token Management](https://urs.earthdata.nasa.gov/documentation/for_users/user_token) of Earthdata Login (last updated 1 July 2026): a user token is valid for 60 days and a user holds at most two. The examples of the page are JSON Web Tokens with the algorithm RS256 and the fields `uid`, `exp`, `iat`, `iss` and `type`. The public pages name no address that checks a user token without a registered application; the pages for integrators ask for a login and were not read. earthaccess 0.19.0 and harmony-py 1.8.0 (code of the packages read) send a token and do not check it. Earthdata Login publishes its public keys at `https://urs.earthdata.nasa.gov/.well-known/edl_ops_jwks.json`; on the day read the address returned one RSA key of 2048 bits with the name `edljwtpubkey_ops`. With an invalid token the addresses `/api/users/<name>` and `/oauth/userInfo` of Earthdata Login answered 401 `{"error":"invalid_token"}`; their answer to a valid token was not tried. |
| Function used | FastAPI routes in `lynkeus.routes`. `sqlite3` of the standard library for the record of sessions, jobs and layers. `multiprocessing` with the start method `spawn` for the operating-system process of a job, which leads a process group of its own; the group receives `SIGTERM` and, 5 seconds later, `SIGKILL`. `secrets` for the keys and names. The signature of a token is verified as RFC 8017, section 8.2.2, describes (RSASSA-PKCS1-v1_5 with SHA-256), with `hashlib` and `pow` of the standard library; no library was added. nginx serves the files of the layers, with the media type `image/tiff; application=geotiff; profile=cloud-optimized` of the [OGC Cloud Optimized GeoTIFF Standard](https://docs.ogc.org/is/21-026/21-026.html) and `application/geo+json` for a STAC Item ([STAC Item Specification 1.1.0](https://github.com/radiantearth/stac-spec/blob/v1.1.0/item-spec/item-spec.md)). |
| Choices of Lynkeus | These numbers come from no source. Session: a key of 256 bits; removal after 7 days without use; at most 5,000 sessions, beyond which a session without jobs and layers makes place for a new one. Earthdata token: forgotten after 30 minutes without a request of the session and after 8 hours at the latest (the two upper values of OWASP). Jobs: 2 run at once (the machine has 2 processors), 20 wait on the machine, 4 wait or run in one session, a job runs for at most 30 minutes, the records of the latest 100 finished jobs of a session are kept. Layers: 50 in a session, 500 megabytes for one layer, 2 gigabytes for a session, 20 gigabytes for all sessions (the machine had 41 gigabytes free on the day read). Request body: 65,536 bytes, in the web service and in the web server. Title of a layer: 200 characters. Public keys of Earthdata Login: kept for one hour, read again at most once a minute. The web server allowed 120 requests a minute from one address before this change. |
| Limits | A token that its user revoked is accepted at the sign-in until it expires; the services of NASA refuse it when a job uses it. A failed job is answered with status 500 whatever its reason. A restart of the server ends the jobs that wait or run. The address of a file of a layer is not bound to the session: whoever knows the 32 random characters can read the file. A process is offered only for asynchronous execution, and its output only by value. The answer in pages uses the parameter `offset`, and the state of a job carries the fields `title`, `inputs` and `layer`; these are additions of Lynkeus to the standard. The interface must ask for the state of its jobs less often than the 120 requests a minute that the web server allows from one address. A fresh interpreter starts for every job, which takes seconds on the loaded machine. The memory of a job is limited only by the limit of the container (1 gigabyte for the service and its jobs together). |
| Tried | 14 Nov 2026, on a private copy of the two containers with the settings of `compose.yaml` (read-only file system, user 10001, 1 gigabyte), with a stand-in process that writes a file of 300,000 bytes after 4 seconds and a stand-in for the public keys of Earthdata Login, driven by Chromium through Playwright 1.65.1. The first request created a session. The browser held the cookie with `HttpOnly`, `SameSite=Strict` and the path `/api`, and the page could not read it. A token with a changed signature was answered with 401, the token of the tests signed the visitor in, and the session received a new key. In three runs of the trial a job passed from accepted to running to successful in 8.9 to 11.8 seconds, with its first report 4.5 to 7.8 seconds after its start, and its results were the layer description. A request for the bytes 1000 to 1999 of the file was answered with 206, `Content-Range: bytes 1000-1999/300000`, the media type of a Cloud Optimized GeoTIFF and the bytes of the file. A request with the entity tag of the file was answered with 304, and a range beyond the file with 416. The folder of the layer, a file of another kind and the record file of the server were answered with 404. A second visitor received 404 for the state, the results and the dismissal of the job of the first, and empty lists of jobs and layers; with the address of the file the second visitor could read it, as the limits state. A running job was dismissed with 200, its address then answered 410, and its operating-system process and its folder were gone. A layer was renamed, and its STAC record carried the new title. The container of the web service was restarted with two jobs running and one waiting, which took 1 to 4 seconds. Afterwards the session was the same, its two layers and two finished jobs were kept, the three other jobs were recorded as failed with a sentence, no process and no folder of them remained, and the visitor was signed out. The web server answered a body of 70,000 bytes with 413, 167 to 171 of 200 requests sent at once with 429, and a request while the web service was stopped with 503, each as problem details. The container of the web service used 47 to 71 MiB of memory without jobs and 137 to 152 MiB with two stand-in jobs running. The browser reported no error apart from the answers with an error status that the trial asked for, and the application page loaded with its 40 images of the background map. The landing page, the conformance declaration, a process description, the state of a job in four states, the job list, the results document and three exceptions were valid against the schemas of the standard (jsonschema 4.26.0). The schemas refuse every whole number among the `additionalParameters` of a process, and every string and every list as an input value of a request, because they join overlapping types with `oneOf`. A description with a whole-number parameter is therefore not valid against `process.yaml`. |
| Not tried | A real Earthdata token: none was made on the account of the team for this work, so the check ran only against tokens signed with a key of the tests, one of them signed by the program OpenSSL 3.0.13. The suite of the OGC for this standard (ets-ogcapi-processes10) was not run. A job that receives a real layer: the functions of the processes are joined by the maintainer. |
| Read on | 14 Nov 2026 |

## Layers through Harmony and the files of Lynkeus

| | |
|---|---|
| NASA Harmony | Harmony clips one layer of a NISAR product file to a box of longitude and latitude and returns it as a GeoTIFF, through the service `nasa/harmony-gdal-adapter`. Its capabilities (`https://harmony.earthdata.nasa.gov/capabilities?collectionId=<collection>`) list the layers that it can deliver for each collection: 20 for GCOV, 23 for GUNW, 43 for GOFF and 13 for SME2, the same for the validated and the provisional collection of a type. The lists are in `api/tests/data/harmony-variables.json`. The file keeps the projection and the cell size of the product, and its cells outside the box hold no data. A licence agreement that is not accepted gives an error when the request is submitted ([Earthdata Cloud Cookbook, harmony-py tutorial](https://pommevilla.github.io/earthdata-cloud-cookbook/transformations/HarmonyPy_intro_tutorial.html)). |
| Product specifications | The names, quantities and units of the layers come from the NISAR product specifications, which the [NISAR Data User Guide](https://nisar-docs.asf.alaska.edu/product-specification/) lists. The revisions read are GCOV, JPL D-102274, revision F (8 July 2026); GUNW, JPL D-102272, revision E (8 Nov 2024); GOFF, JPL D-105010, revision C (8 Nov 2024); SME2, JPL D-107677, revision C (8 Nov 2024). GCOV: the terms of the covariance matrix are normalized to gamma nought by radiometric terrain correction, a diagonal term (`HHHH`, `HVHV`, `VHVH`, `VVVV`) is the backscatter of one channel, the layer `rtcGammaToSigmaFactor` turns gamma nought into sigma nought, and the cell size is 10, 20 or 80 m with the range bandwidth (table 2-3, sections 4 and 4.3.1). The values are linear: the product file of 21 Oct 2026 gives `10*log10(<GCOV_TERM>)` as the conversion to decibels (field `outputBackscatterDecibelConversionFormula`). GUNW: the wrapped interferogram and its coherence are at 20 m, and the unwrapped phase (radians), its coherence, the connected components, the ionosphere phase screen and the pixel offsets (metres) are at 80 m. GOFF: the pixel offsets are at 80 m in three offset layers, numbered from the finest resolution (`layer1`) to the coarsest (`layer3`). SME2: soil moisture in cubic metres of water in a cubic metre of soil, on the EASE-Grid 2.0 at 200 m, with -9999 in a cell without data. |
| Standards of the files | STAC 1.1.0, [Item specification and common metadata](https://github.com/radiantearth/stac-spec/tree/v1.1.0): `datetime` may be null when `start_datetime` and `end_datetime` are given; a band carries `data_type`, `nodata` (a number or the text `nan`), `unit` (UCUM or UDUNITS-2 is strongly recommended) and `statistics`; the link `via` leads to the record that is not STAC from which an Item was made. Extensions [projection 2.0.0](https://github.com/stac-extensions/projection/tree/v2.0.0) (`proj:code`, `proj:wkt2`, `proj:shape`, `proj:transform`, `proj:bbox`), [raster 2.0.0](https://github.com/stac-extensions/raster/tree/v2.0.0) (`raster:sampling`, `raster:spatial_resolution`) and [processing 1.2.0](https://github.com/stac-extensions/processing/tree/v1.2.0) (`processing:lineage`, `processing:level`, `processing:datetime`, `processing:software`, and the link `derived_from` to the Item of an input). Cloud Optimized GeoTIFF: the [COG driver of GDAL](https://gdal.org/drivers/raster/cog.html) writes tiles of 512 cells by default and reduced copies (overviews) until the smallest is not larger than a tile, and it takes the resampling of the reduced copies and the predictor of the compression as options. |
| GIS programs | QGIS: the stretch "Cumulative count cut" removes outliers, and its standard range is 2 % to 98 % ([QGIS user manual, Raster Properties](https://doc.qgis.org/testing/en/docs/user_manual/working_with_raster/raster_properties.html)). ArcGIS Pro: not read. |
| Colour scales | Matplotlib, [Choosing Colormaps](https://matplotlib.org/stable/users/explain/colors/colormaps.html): a sequential scale suits a quantity that has an order (`viridis` is perceptually uniform; `YlGnBu` and `gray` are sequential), a diverging scale suits a quantity with a middle value such as zero (`RdBu`), and a qualitative scale suits classes without order (`tab10`). |
| Function used | harmony-py 1.8.0 (code of the installed package read): `Client(token=...)` signs each request with the token; `Client()` takes the credentials of the environment and checks them with Earthdata Login; `submit` returns the identifier of a job, `status` its state, progress and message, `cancel` cancels it, and `result_urls` and `download` fetch the result. It asks for a job in every case (`forceAsync=true`), and it removes the token from a request that is redirected to a host other than Earthdata Login. Rasterio 1.5.2 with GDAL 3.12.2 reads and writes the GeoTIFF files; in the image `python:3.13-slim` it needs the system library `libexpat1`. In the tests, `cog_validate` of rio-cogeo 7.0.4 checks the files in strict mode, and jsonschema 4.26.0 checks the records against the published schemas, which are kept in `api/tests/data/stac/`. |
| Layers | The table below lists the layers that `layers_of` offers. The name of a layer is its path in the product inside the group of the main frequency band (`/science/LSAR/<type>/grids/frequencyA/`; for SME2 `/science/LSAR/SME2/grids/`). Every layer of the table was received from Harmony on real data before it was listed, for the channels named under "Tried on real data". `layers_of` gives each layer with its smallest cell size, so that the interface can estimate the cells of an area with the same rule as the server. |
| Choices of Lynkeus | **File.** 32-bit real numbers, `nan` in a cell without data whichever value the product uses, tiles of 512 cells, DEFLATE compression with the floating-point predictor. On the backscatter of 21 Oct 2026 (15.0 million cells; 73.2 MB as Harmony delivers it, with LZW) the sizes were: LZW 71.5 MB, DEFLATE 59.0 MB, DEFLATE with the floating-point predictor 52.0 MB (written in 3.6 s), the same at level 9 51.0 MB (14.4 s), ZSTD with the predictor 50.9 MB, LERC without loss 76.2 MB, no compression 89.1 MB. DEFLATE was taken over ZSTD, which is 2 % smaller, because it is the older of the two in TIFF files and more readers decode it; this reason comes from no source. **Reduced copies.** Lynkeus makes them from the values at full resolution and never passes on those of Harmony: by averaging for a quantity (the average of a power is taken on the linear values, and a cell without data is left out), and by the most frequent value for classes. **Legend.** Three rules give the range from the values: the 2nd and the 98th percentile (the standard of QGIS); for a quantity with a sign, the 98th percentile of the absolute values on both sides of zero; for classes, the lowest and the highest value. Coherence and the correlation peak, which lie between 0 and 1 by definition, keep that range. When a rule gives one value twice, the range is the lowest and the highest value, and for a layer of one value it runs from half a unit below to half a unit above it. **Colour scales.** The names are those of Matplotlib, with `grey` for its `gray`: `grey` for backscatter and coherence, `RdBu` for the quantities with a sign, `YlGnBu` for soil moisture, `viridis` for the other quantities and `tab10` for classes. The class of each scale follows Matplotlib; the choice of grey for radar images and of `YlGnBu` for soil moisture comes from no source. **Units.** As the CF conventions write them: `1`, `rad`, `m`, `m3 m-3`. **Record.** The description of a layer holds days, so the record gives the period from the start of the first day to the end of the last one and leaves `datetime` null. It has no `self` link, because the files do not know the address of the site. **Limits of size and time.** A layer has at most 25 million cells: the process that writes one used at most 353 MB of memory for 15.0 million cells and 508 MB for 25 million, in a container limited to 1 GB. The size is estimated before the request from the area and the smallest cell size of the layer, and counted again on the file received. Lynkeus waits for a job of Harmony at most 30 minutes, asks for its state every 3 seconds, as harmony-py does, and gives up after three questions in a row without an answer. The progress of a job of Harmony fills the part from 5 to 80 of the progress of a layer. These numbers come from no source. |
