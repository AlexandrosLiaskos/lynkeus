# Research note: status bar and View tab

This note records, for each function of the status bar and of the View tab, how GIS programs offer it, which
existing function Lynkeus uses for it, the limits found and what could not be confirmed. Every source was read
on the date given. The pages of ArcGIS Pro, QGIS, the Open Geospatial Consortium and ISO were read through a web
search, which returns the passages of a page and not the whole page. The code of OpenLayers was read in full from
the npm package.

## Place and contents of the status bar

| | |
|---|---|
| ArcGIS Pro | The status bar stands at the bottom of the map view. The scale list is at the bottom corner of each view ([Map scales and scale properties](https://pro.arcgis.com/en/pro-app/latest/help/mapping/navigation/map-scales-and-scale-properties.htm)). The coordinates of the pointer are displayed on the status bar, by default in decimal degrees, and an arrow beside them opens the choice of another display unit ([Navigate maps and scenes](https://doc.esri.com/en/arcgis-pro/latest/get-started/navigate-your-data.html)). Two buttons at the lower right of the view, Pause Drawing and Refresh, concern the drawing; the Refresh button spins while the map draws data ([Navigation](https://pro.arcgis.com/en/pro-app/latest/help/mapping/navigation/navigation-in-arcgis-pro.htm)). The count of selected features was not read. |
| QGIS | The status bar holds, from left to right: the locator bar, a place for messages and a progress bar for long operations such as the rendering of several layers, the coordinate of the pointer, the scale with a selector of predefined scales, the magnifier, the clockwise rotation of the map view in degrees, the Render checkbox, and a button with the EPSG code of the project's coordinate reference system ([QGIS GUI, Status Bar](https://docs.qgis.org/3.44/en/docs/user_manual/introduction/qgis_gui.html)). |
| Choices of Lynkeus | One row under the map, in this order: the scale, the coordinates, the list of formats, the value of the selected layer; and at the right end the word "Loading" while the map loads, the rotation when it is not zero, the projection, and the credits of the layers of the map. The bar does not offer the magnifier of QGIS, which enlarges the map without a change of scale, nor the pause of drawing. Lynkeus has no selection of features, so the bar shows no count of them. |
| Width of the values | The figures have one width each (`font-variant-numeric: tabular-nums`), and every value stands in a field that takes the width of the widest text it can show. The bar therefore keeps its form while the pointer moves. The number of decimals of the coordinates follows the size of a pixel at the centre of the map, so it changes with the zoom and with the latitude of the centre, and the fields change their width only then. |
| Narrow window | In a window too narrow for one row the parts of the bar go on to a second and a third row, and none is left out. In a window narrower than 640 pixels the list of formats stands beside the scale on the first row, and the projection is written by its code alone. How ArcGIS Pro shortens its bar in a narrow view was not found in its documentation; the wrapping is a choice of Lynkeus. |
| Tried in a browser | 14 Nov 2026. Chromium 158.0.8127.18, through Playwright 1.65.1, on a private copy of the built page behind `web/nginx.conf`, which sends the security policy of the site: no error on the console and no failed request. In a window of 1440 by 900 pixels the bar took one row, 27 pixels high with its upper line. While the pointer stood on nine places of the map, at three scales, the place and the width of every part of the bar stayed the same within each view, in each of the four formats. The controls of the bar were 24 pixels high: the scale field 120 pixels wide, its button 24 and the list of formats 172. In a window of 390 by 800 pixels the page did not scroll sideways, and the bar took two rows (53 pixels) in decimal degrees and in degrees with minutes and seconds, and three rows (79 pixels) in UTM and in the coordinates of the map projection. |
| Not tried in a browser | In that trial the list of formats was cut to its arrow in the narrow window. It was then given its place beside the scale, at its full width of 172 pixels; the scale part is 156 pixels wide, and the two with the space between them take 340 of the 374 pixels of the row. This arrangement was not seen in a browser. |

## Scale

| | |
|---|---|
| Definition | The Open Geospatial Consortium defines a scale denominator with respect to a "standardized rendering pixel size" of 0.28 mm by 0.28 mm, because the true size of a pixel of the screen is not known to a web page (Web Map Tile Service Implementation Standard 1.0.0, OGC 07-057r7, clause 6.1, as quoted by [the profile DGIWG 124](https://portal.dgiwg.org/files/74566); the same definition is in the [Symbology Encoding Implementation Specification 1.1.0, OGC 05-077r4, clause 10.2](https://repository.oceanbestpractices.org/bitstream/handle/11329/1122/05-077r4_OpenGIS_Symbology_Encoding_Implementation_Specification.pdf)). The scale 1 : n of a map is therefore n = (length of one pixel on the ground, in metres) / 0.00028. |
| OpenLayers 10.11.0 | `ol/control/ScaleLine` assumes the same pixel: its constant `DEFAULT_DPI` is 25.4 / 0.28. In its text mode (the default) it draws a line whose length in pixels is a round distance (1, 2 or 5 times a power of ten) divided by the length of a pixel on the ground at the centre of the map. In its bar mode it can also write the scale as "1 : n", computed as the length of that pixel times 1000 / 25.4 inches per metre times the dots per inch, which equals the length divided by 0.00028. Both modes take the length of a pixel on the ground from `getPointResolution` of `ol/proj`, at the centre of the view. |
| Change with latitude | In Web Mercator one pixel covers `resolution / cosh(y / 6378137)` metres on the ground, which is the resolution times the cosine of the latitude (the function `getPointResolution` of the projection EPSG:3857 in `ol/proj/epsg3857.js`). The scale at latitude 60 degrees is therefore twice as large as at the equator at the same zoom level. |
| ArcGIS Pro | The scale list at the bottom corner of the view accepts a typed scale and offers a list that the user can customize ([Map scales and scale properties](https://pro.arcgis.com/en/pro-app/latest/help/mapping/navigation/map-scales-and-scale-properties.htm)). For many maps the scale listed in the map view is the scale at a location along the equator ([Scale bars](https://pro.arcgis.com/en/pro-app/latest/help/layouts/scale-bars.htm)). |
| QGIS | The scale display of the status bar has a selector of predefined scales. The predefined scales of a new profile are 1:1,000,000, 1:500,000, 1:250,000, 1:100,000, 1:50,000, 1:25,000, 1:10,000, 1:5,000, 1:2,500, 1:1,000 and 1:500 (the key `scales` of a [QGIS3.ini file](https://issues.qgis.org/attachments/14560/QGIS3.ini)). |
| Function used | `scaleAt` in `web/src/statusbar/scale.ts`: `getPointResolution(projection, resolution, centre, "m") / 0.00028`. The scale is that of the centre of the map, as the scale bar of OpenLayers on the same map, and not that of the equator. `showScale` sets the resolution of the view that gives a typed or chosen scale at the centre. |
| The control | An editable combobox of the ARIA Authoring Practices Guide without autocompletion: the keyboard focus stays in the field, the down and up arrows open the list and move through it, Alt with the down arrow opens it without a choice, Enter chooses, Escape closes the list and a second Escape drops the typed text ([WAI-ARIA Authoring Practices 1.2, Combobox](https://www.w3.org/TR/2021/NOTE-wai-aria-practices-1.2-20211129/), [Editable Combobox without Autocomplete Example](https://www.w3.org/TR/2021/NOTE-wai-aria-practices-1.2-20211129/examples/combobox/combobox-autocomplete-none.html)). The `datalist` element of the browser was not used, because it hides the scales that do not contain the text of the field. The combo box of the U.S. Web Design System was not used, because it accepts only the values of its list. |
| Choices of Lynkeus | The list holds the eleven predefined scales of QGIS and six smaller scales for a map of the whole Earth: 1:2,500,000, 1:5,000,000, 1:10,000,000, 1:25,000,000, 1:50,000,000 and 1:100,000,000. These six come from no source. A typed scale may be written as 1:25,000, 1/25000 or 25000. The scale is written with a comma between the thousands. |
| Limits | The scale holds for a screen whose pixels are 0.28 mm wide. On another screen the true scale differs by the ratio of the pixel sizes; a web page cannot learn the true size. OpenLayers computes the length of a pixel on a sphere. On the WGS 84 ellipsoid the length of the same pixel, computed with pyproj 3.7.2, differs by -0.67 % (north to south, at the equator) to +0.25 % (east to west, at latitude 60 degrees). A map does not zoom out further than the width of one world, nor in further than zoom level 28, so the largest and the smallest scale that the map can show depend on the width of the window and on the latitude; a scale outside them gives the nearest one and a message. |
| Tried in a browser | 14 Nov 2026, in the same browser. The size of one pixel of the map was measured without the scale: it is the difference between the X coordinates that the bar shows under the pointer at two places 600 pixels apart, divided by 600. The latitude of the centre follows from its Y coordinate. The expected scale is that size times the cosine of the latitude, divided by 0.00028. After 1:250,000 was typed: pixel 139.6633 m, latitude 59.9199 degrees, expected 1:250,003, shown 1:250,000. The largest difference is 0.0010 %, which is the precision of the measured pixel. The first view asks for zoom level 2, at which the world is 1024 pixels wide. The map was 1440 pixels wide, and OpenLayers does not show more than one world across a map, so the pixel is 40,075,016.686 m / 1440 = 27,829.8727 m (zoom 2.4919); the measured pixel was 27,829.8733 m. The text "abc" gave the message that it is not a scale. The scale 1:1 gave the message that the map cannot show it, and the map showed the largest scale that it can. |

## Coordinates

| | |
|---|---|
| ArcGIS Pro | The coordinates of the pointer are shown in the location units of the map, by default decimal degrees; the list beside them changes the format ([Navigate maps and scenes](https://doc.esri.com/en/arcgis-pro/latest/get-started/navigate-your-data.html)). Location units include metres, decimal degrees and degrees with minutes and seconds ([Set unit options for editing](https://pro.arcgis.com/en/pro-app/latest/help/editing/add-project-units-for-editing.htm)). The Map Viewer of ArcGIS displays coordinates as decimal degrees, degrees minutes seconds, degrees decimal minutes, MGRS, UTM, USNG, or in the coordinate system of the basemap ([Find location coordinates](https://enterprise.arcgis.com/en/portal/11.0/use/find-location-coordinates-mv.htm)). |
| QGIS | The status bar shows the coordinate of the pointer in the coordinate reference system of the project; a button changes it to the extent of the view ([QGIS GUI, Status Bar](https://docs.qgis.org/3.44/en/docs/user_manual/introduction/qgis_gui.html)). |
| ISO 6709 | For a reader, the latitude comes before the longitude, the hemisphere is given by the letters N, S, E and W directly after the digits, the two values are separated by a space, degrees, minutes and seconds carry their symbols without a space, and minutes and seconds below ten carry a leading zero; examples: 50°40′46″N 95°48′26″W ([ISO 6709, summary of Annex D of the 2008 edition](https://en.wikipedia.org/wiki/ISO_6709)). The edition of 2022 states that 50.0795725 decimal degrees is 50°04'46.461" and that coordinates are given to a resolution commensurate with the accuracy of the position ([ISO 6709:2022, preview of the standard](https://cdn.standards.iteh.ai/samples/75147/ae8eed3277634c52b6d4b0e0d2c29980/ISO-6709-2022.pdf)). The full text of the standard was not read. |
| UTM | A Universal Transverse Mercator coordinate is a zone number, a hemisphere, an easting and a northing in metres. The system covers the latitudes from 80 degrees south to 84 degrees north. The easting is 500,000 m at the central meridian of a zone; the northing is 0 m at the equator in the northern hemisphere and 10,000,000 m at the equator in the southern one. A letter after the zone number can mean the hemisphere or a band of latitude of the Military Grid Reference System, and the two must not be confused ([NGA, Coordinate Systems](https://earth-info.nga.mil/?action=coordsys&dir=coordsys)). |
| OpenLayers 10.11.0 | `ol/proj/utm` gives the projections EPSG:32601 to 32660 and 32701 to 32760 and their transforms; `ol/proj` creates them when `transform` is called with such a code. The code states that the transforms are approximate and adapted from the Python package `utm` of Tobias Bieniek. `toLonLat` brings the longitude of a repeated world back between -180 and 180 degrees. |
| Function used | `writeCoordinate` in `web/src/statusbar/coordinates.ts`, with `toLonLat` and `transform` of `ol/proj`. |
| Choices of Lynkeus | Four formats: decimal degrees (42.775°N 70.975°W), degrees with minutes and seconds (42°46′30″N 70°58′30″W, with the prime and the double prime as symbols), UTM (Zone 19 North 338432 m E 4737721 m N) and the coordinates of the map projection (X -7900901 m Y 5277787 m). The hemisphere of a UTM position is written as a word, so that it cannot be read as a band of latitude. The number of decimals follows the size of one pixel at the centre of the map, as the standard asks: one unit of the last digit is not longer than that pixel, up to 7 decimals of a degree, 3 of a second and 2 of a metre. These three limits come from no source. While the pointer is not over the map, the bar shows the coordinates of the centre of the map, with the word "Centre" in the place of "Pointer", so that a user of the keyboard or of a touch screen also reads coordinates. |
| Limits | The zones are 6 degrees wide everywhere. The wider and narrower zones around south-west Norway and Svalbard, which belong to the grid zones of the Military Grid Reference System, are not applied, so a point there is given in the zone of its longitude. Outside the latitudes of the system the bar shows "No UTM zone"; the polar system (UPS) is not offered. Degrees with decimal minutes, MGRS and USNG are not offered. The names of projections are given for EPSG:3857 and EPSG:4326 only; another projection would be shown by its code. |
| Tried | 14 Nov 2026. In the tests, seven positions (the pilot area, Athens, Rio de Janeiro, Tromsø, a point on the edge of a zone at the equator, Sydney and a point near 84 degrees north) give the zone and the hemisphere of pyproj 3.7.2 (PROJ 9.8.1), and an easting and a northing that differ from it by less than 5 mm. Over 126 positions across zone 19, from 79.9 degrees south to 83.9 degrees north, the largest difference from pyproj was 0.92 mm. |
| Tried in a browser | 14 Nov 2026, in the same browser. The pointer stood on five places of a view in which one pixel is 13,914.94 m, on three places at 1:250,000 near latitude 60 degrees, where one pixel is 139.66 m, and on one place of the pilot area at 1:249,994, where one pixel is 95.36 m. The expected position of each place follows from the centre of the map, the measured size of a pixel and the distance of the place from the centre in pixels; pyproj converts it to degrees and to UTM. At all nine places the X and Y that the bar showed differ from the expected ones by less than 1 m, which is their last digit; the degrees, and the degrees with minutes and seconds, differ by less than one unit of their last digit; the zone is the same, and the easting and the northing differ by less than 1 m. In the pilot area, 120 pixels east and 60 pixels north of the centre, the bar showed 42.8127°N 70.8713°W, 42°48′46″N 70°52′17″W, Zone 19 North 347008 m E 4741711 m N and X -7889358 m Y 5283501 m; pyproj gives 42.81267°N 70.87130°W and Zone 19 North 347008.5 4741710.4. The comparison takes into account that the element of the map was 717.5625 pixels high and that OpenLayers draws 718 rows into it, so one row of the map is 0.99939 of a pixel of the screen. When the pointer left the map the bar showed the centre again. With the keyboard focus on the map, three presses of the right arrow key moved the centre from 0.00°E to 19.27°E. |

## Value of the selected layer

| | |
|---|---|
| ArcGIS | The Pixel Inspector of ArcMap shows the values of the cells of a raster while the pointer moves over it ([Using the Pixel Inspector](https://desktop.arcgis.com/en/arcmap/latest/manage-data/raster-and-images/using-the-pixel-inspector.htm)). In ArcGIS Pro a click on a raster opens a pop-up with the value of the cell, according to an answer on the [Esri Community](https://community.esri.com/t5/arcgis-pro-questions/arcgis-pro-equivalent-of-qgis-value-tool/td-p/1067980); the documentation of ArcGIS Pro for this was not read. |
| QGIS | Not read. The question above names the Value Tool, an additional program of QGIS that shows the value under the pointer. |
| Function used | `valueAt` in `web/src/contents/display.ts`, which reads the value that the layer has drawn at a pixel of the map, and `selectedLayerStore` in `web/src/contents/state.ts`. The status bar shows the name of the layer that is selected in the Contents pane and its value under the pointer or, while the pointer is not over the map, at the centre of the map. The unit is written as the legend of the Contents pane writes it, and a quantity without dimension has none. Where the layer has no value the bar shows "No data". |
| Choices of Lynkeus | The value is written with six significant figures, because the files hold numbers of 32 bits, which carry seven. It is read at most once for each frame that the browser draws, and again whenever the map has finished drawing, because the file of a layer arrives in parts. A name longer than 256 pixels is cut. These numbers come from no source. |
| Limits | The value is the one drawn. At a small scale it is the mean of the cells that one drawn cell covers, as the function `valueAt` states, and not the value of one cell of the file. |
| Tried | 14 Nov 2026. Five cells of the sample file `gcov-hhhh-20261021.tif` and five of `gunw-coherence-20261009-20261021.tif` were read with rasterio 1.5.2 (GDAL 3.12.2). A test gives the ten values to the function that writes a value and finds the text that Python writes for them with six significant figures, for example 0.285015 for 0.2850151062011719 and 0.0283031 for 0.028303146362304688. The tests give the bar a value in the place of the reading of the map, and find that the bar reads once in a frame, at the pixel of the pointer or at the centre. |
| Not tried in a browser | The whole function. The Contents pane does not yet draw a layer on `main`, and the trials in a browser ended before it did. The value that the bar shows for a cell of a layer on the map was therefore not compared with the file. |

## Projection, rotation and loading

| | |
|---|---|
| QGIS | A button at the right end of the status bar shows the EPSG code of the coordinate reference system of the project. A field shows and sets the clockwise rotation of the map view in degrees. A progress bar shows while several layers are rendered ([QGIS GUI, Status Bar](https://docs.qgis.org/3.44/en/docs/user_manual/introduction/qgis_gui.html)). |
| ArcGIS Pro | The Refresh button at the lower right of the view spins while the map draws data ([Navigation](https://pro.arcgis.com/en/pro-app/latest/help/mapping/navigation/navigation-in-arcgis-pro.htm)). |
| Names | The EPSG Geodetic Parameter Dataset, version 12.029, as read through pyproj 3.7.2: EPSG:3857 is "WGS 84 / Pseudo-Mercator" and EPSG:4326 is "WGS 84". |
| OpenLayers 10.11.0 | The rotation of a view is in radians, positive clockwise. The map sends the events `loadstart` when it starts to load images or layers and `loadend` when everything of the present view is loaded. The default interactions of the map, which Lynkeus keeps, turn the map when it is dragged with the Alt and Shift keys or with two fingers. |
| Choices of Lynkeus | The projection is written by its name and its code. The rotation is shown in degrees with one decimal, from -180 to 180, only when it is not zero, with a button "North up" that sets it to zero, as the button of the same name on the Map tab does. The bar shows the word "Loading" while the map loads. It shows no moving sign, because the interface has no animation. |

When each image of the background map was held back for 0.15 seconds, the bar showed the word Loading in the first 5 of 74 readings taken about every 0.1 seconds after the page opened, and nothing in the later ones. |

## Scale bar and credits on the map

| | |
|---|---|

## View tab

| | |
|---|---|
| ArcGIS Pro | The group Windows of the View tab holds Catalog Pane, Catalog View, Contents and Reset Panes; Reset Panes for Mapping (Default) opens the Contents and Catalog panes and closes all other panes ([Use the Catalog pane](https://pro.arcgis.com/en/pro-app/3.4/help/projects/the-project-pane.htm), [Introducing ArcGIS Pro](https://pro.arcgis.com/en/pro-app/3.4/get-started/introducing-arcgis-pro.htm)). |
| Office | The View tab of Word has a group Show with the check boxes Ruler, Gridlines and Navigation Pane ([Microsoft Q&A](https://learn.microsoft.com/en-us/answers/questions/5340514/there-is-no-ruler-option-under-the-view-tab-in-wor)). The View tab of Excel 2007 had the group Show/Hide (Ruler, Gridlines, Formula Bar, Headings) and the command Full Screen in the group Workbook Views ([tutorial of Internet4Classrooms](https://www.internet4classrooms.com/technology_tutorials/07_excel_view_tab.htm)). The pages of Microsoft's own documentation were not read. |
| QGIS | The menu View holds Decorations, Panels, Toolbars, Toggle Full Screen Mode (F11), Toggle Panel Visibility and Toggle Map Only, which hides the panels, the toolbars, the menus and the status bar ([QGIS GUI, View](https://docs.qgis.org/3.44/en/docs/user_manual/introduction/qgis_gui.html)). |
| Browser | `Element.requestFullscreen()` shows an element over the whole screen and returns a promise; it needs an action of the user. The browser sends the event `fullscreenchange` when it enters or leaves the full screen, and `document.fullscreenElement` is the element that fills the screen, or null. Most browsers leave the full screen on the Escape key ([MDN, Element: requestFullscreen()](https://developer.mozilla.org/en-US/docs/Web/API/Element/requestFullscreen), [MDN, Document: fullscreenchange event](https://developer.mozilla.org/docs/Web/API/Document/fullscreenchange_event)). `document.fullscreenEnabled` tells whether the full screen is available. |
| Functions | Group Windows: Contents and Catalog (each shows or hides its pane and is pressed while the pane is on the page; a press on the button of a pane that stands behind the pane of a tool brings it to the front), Reset panes, Full screen. Group Show, after the group of the same name in Office: Status bar. |
| Icons | The icons come from the set of the U.S. Web Design System 3.14.0, whose 245 names were read from its file `sprite.svg`. Contents takes `list`, Catalog `folder`, Reset panes `undo` and Full screen `zoom_out_map`. The set has no picture of a status bar. Status bar takes `info_outline`, because the bar gives information on the map. It is the nearest picture of the set and not an exact one; the label under the icon names the button. |
| Choices of Lynkeus | Full screen shows the frame that holds the map and the messages over the whole screen, so that a message still reaches the user; the ribbon, the panes and the status bar are not shown then. The keyboard focus moves to the map and returns to the button afterwards. The button is pressed while an element fills the screen; it follows the event of the browser, so the Escape key of the browser also releases it. In a browser that cannot fill the screen the button is inactive. |
| Limits | In the full screen the button itself is not on the screen; the user leaves with the Escape key or with the means of the browser. Reset panes opens the Contents pane and the Catalog pane at their first width and closes the pane of every tool, as Reset Panes for Mapping (Default) does; in a window narrower than 1024 pixels the first state of the two panes is closed. The Catalog pane is drawn only after a search, and the Contents pane only when its owner draws it. The button of a pane is pressed only while the pane is on the page; a press on the button of a pane that has nothing to show gives the message that the pane has nothing to show yet. |
| Tried in a browser | 14 Nov 2026, in the same browser, at 1440 by 900 pixels. Reset panes left the page without a fault. Status bar removed the bar from the page and brought it back. Scale bar removed the scale bar from the map and brought the same one back, with its label. Full screen, started with the Enter key: the element that filled the screen was the frame of the map, the keyboard focus was on the map, and the button was pressed; after the full screen ended the button was released and the keyboard focus was on it again. The Escape key that Playwright sends to a headless Chromium did not end the full screen, so the end was produced with `document.exitFullscreen()`, which makes the browser send the same event. |
